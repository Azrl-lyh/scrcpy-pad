# 基于 scrcpy 的手机控制软件

### 设计目的：已有的 scrcpy 二次创作程序不好用，功能也比较单薄。基于我生活中对各种模拟器程序的使用经历，我决定自己制造一个模拟器风格、用起来顺手的程序。

具体的使用方式下面都写清楚了，照着看没问题。这里主要给新手朋友普及一下怎么安装使用，再讲一下这程序的独特之处。

> 本 README 对应当前版本 \*\*0.2.1\*\*。程序把电脑的键盘、鼠标映射成手机屏幕上的触控操作，游戏画面由 scrcpy 本体窗口显示，两者互不干扰。

## 注意：使用前请先打开 USB 调试

使用本程序时，手机必须用数据线连接电脑，并打开 USB 调试。打开方法：在设置里搜索“USB 调试”，点进相关界面启用。如果你是小米的系统，找到“USB 调试”功能和“USB 调试（安全设置）”功能，两个都启用（会有安全风险提示）。其他品牌同理打开相应选项，不会的去网上搜教程，教得很详细。

**注意：USB 调试属于有风险的功能。请务必确保手机连接的设备是可信的。如果手机需要频繁接入不同的电脑，请在使用后及时关闭 USB 调试功能。**

## 适用场景

* 在电脑上用键盘鼠标玩安卓手机游戏，尤其是**以按键为主、不对灵活滑动操作做高要求**的游戏（动作、二游、模拟器类操作等）。
* 想在多款游戏之间快速换车：程序支持一份配置里的多套“按键组合”，按一个切换键即可整套切换。
* 追求低延迟、高清晰度：画面延迟**完全取决于手机与电脑的连接速度**，与网络无关。
* 需要更精细的操作：多个摇杆、临时摇杆、FPS 鼠标瞄准、后坐力补偿、宏、轨迹录制。

## 获取与下载

* **程序本体**：在本仓库的 Releases 页面下载对应平台的压缩包 —— Windows 版是 scrcpy-pad.exe，Linux 版是无后缀的 scrcpy-pad。
* **scrcpy**：程序依赖 scrcpy 提供 scrcpy-server 与控制能力。作者会随程序发布提供配套的 scrcpy 压缩包；如果不想花时间找别处下载、或对新版本不作要求，直接用配套那份即可：

  * Windows：scrcpy-win64-v3.3.3.zip
  * Linux：scrcpy-linux-x86\_64-v3.3.3.tar.gz
* 所谓“同目录”，指的是 scrcpy-pad 程序，和以 scrcpy-xxxx 为名的文件夹放在同一目录下。如果程序找不到 scrcpy，也可以在程序里手动选择，在左栏按提示从相应目录选择，直到 scrcpy、scrcpy-server 和 adb 都被寻找到即可。

## 安装

### Windows

拿到 scrcpy-pad 的 Windows 版（scrcpy-pad.exe）和 scrcpy（Windows 版），把 scrcpy 解压到程序同目录后，双击运行即可。

### Linux

拿到 scrcpy-pad 的 Linux 版（无 .exe 后缀）和 scrcpy（Linux 版），然后运行以下命令修改权限：

```
sudo usermod -aG input $USER
```

输入管理员密码，注销并重新登录即可。之后就可以正常运行了。

## 从源代码安装（可选阅读）

如果你只是想用这个程序，不需要阅读这些内容。

GitHub 在国内可以正常访问，但是容易遭受 DNS 污染，从而加载网页、下载文件缓慢，甚至出现无法访问的情况。解决上不去有两个常用办法：**第一，尝试更换浏览器 DNS**，具体教程网上一大把；不想找的直接在浏览器设置页面搜索“基于 HTTPS 的 DNS”，点击高级设置，设置成 Cloudflare（1.1.1.1）就行。除了 Cloudflare，其他选项也可以试一试，用完记得切回默认。**第二，使用加速工具**，在加速页面里勾选 GitHub 就能用了；用代理也可以，出现证书问题就找 AI 解决。下载缓慢的话，还可以使用 GitHub 镜像站把下载链接粘进去测速、选最快的中转。

此外，本程序需要 Rust 开发环境。安装 Rust 去官网下载即可；遇到下载缓慢可以去镜像源（如中科大、清华）下载。你大概率会下载一个名为 rustup-init.exe 的程序，它只是一个下载器，在含有它的目录下打开终端，输入：

```
$ENV:RUSTUP\_DIST\_SERVER='https://mirrors.ustc.edu.cn/rust-static'
$ENV:RUSTUP\_UPDATE\_ROOT='https://mirrors.ustc.edu.cn/rust-static/rustup'
.\\rustup-init.exe
```

来实现临时更换源并安装的效果（Windows）。Linux 使用国内源一键安装脚本即可：

```
export RUSTUP\_DIST\_SERVER=https://rsproxy.cn
export RUSTUP\_UPDATE\_ROOT=https://rsproxy.cn/rustup
curl --proto '=https' --tlsv1.2 -sSf https://rsproxy.cn/rustup-init.sh | sh
```

另外，本程序依赖 scrcpy，你需要下载这个程序，并记下它所在的目录（那里面有 scrcpy.exe、adb.exe、scrcpy-server，Linux 下没有 .exe 后缀）。

安装环境配置好后，下载仓库（或 git clone），源代码就在里面。初次运行 启动.bat（Windows）或 启动.sh（Linux）可能会下载一些依赖，大概四百多条，保持网络畅通大约需要 5 分钟左右；初次启动或触发重新编译时，程序会编译，大概需要两三分钟（处理器核越多、越先进越快）。之后每次运行启动脚本就会直接打开程序。程序构造相关文件和二进制文件在目录下的 target 文件夹内。详见后面的「从源码构建」。

## 本程序的独特之处

### 0\. 跨平台，理论支持任意种类游戏

本程序完全开源，理论支持任何兼容 Rust 的操作系统编译并安装使用。从二游到操作游戏，凡是不对灵活滑动操作做要求的、主要以按键为主的游戏，本程序都能应用。

### 1\. 多个摇杆，摇到爽

摇杆在屏幕上可以存在多个，可自由添加和删除。并且本程序支持**临时摇杆**：按下一个键，你自定义的某处摇杆就会显现，临时取代那些键本来的功能（甚至可以取代之前的摇杆），直到你松手才恢复原样；也可以把触发改为一次按下开启、二次按下关闭。非常灵活自由。

### 2\. 按键灵活，自由度高

你可以设置按键触发为按下后固定秒数抬起，也可以设置为按下不松手来一直算作按下。你甚至可以一键实现复杂的滑动操作，比如画直线、画圆、画方，也可以设置模拟手指移动速度的速度函数；还可以一键实现撤回、回主页等系统级操作。

### 3\. 清晰度高，延迟低

画面延迟**完全取决于手机与电脑的连接速度**，你的数据线和接口越快，游戏延迟就越低，与网络和系统没有半点关系（当然，古早系统连画面和数据的简单搬运都费力，另当别论）。

### 4\. 原程序社区成熟，口碑极佳

scrcpy 作为投屏软件是当之无愧的业界领先，程序轻量高效、社区活跃，无需担心。本程序亦支持 scrcpy 参数设置，可以完全发挥出 scrcpy 应有的实力。

# scrcpy-pad 完整使用说明

当前版本：**0.2.1**

基于 scrcpy 的键鼠映射工具：在电脑上把键盘按键、鼠标操作映射成手机屏幕上的触控操作。

```
键盘/鼠标 ──► ┌─────────────┐      ┌──────────────┐      ┌──────────┐
              │  scrcpy-pad │ ───► │ scrcpy-server│ ───► │   手机    │
              │  (映射引擎)  │ TCP  │ (仅控制通道)  │ adb  │  游戏画面 │
              └─────────────┘      └──────────────┘      └──────────┘
                    画面由 scrcpy 本体窗口显示，与本程序互不干扰
```

## 1\. 安装与首次配置

### 1.1 环境要求

|依赖|说明|
|-|-|
|scrcpy|提供 scrcpy-server 与画面窗口|
|adb|通常随 scrcpy 一起提供；Linux 也可用系统包管理器安装|
|手机|已开启 USB 调试，并用数据线连接电脑|
|Rust|仅从源码构建时需要|

Linux 额外要求（读取输入设备需要 input 组权限）：

```bash
sudo usermod -aG input $USER
# 之后必须注销并重新登录
```

Windows 无需特殊权限。

### 1.2 指定 scrcpy 路径

1. 启动程序后，程序会自动寻找 scrcpy 并检测版本，左栏会显示结果。
2. 找不到时，在左栏 **scrcpy 管理** 里直接填/选 scrcpy 所在**目录**（最省事，填一个就够），其余会自动从同目录补齐；也可以只填 scrcpy.exe / scrcpy-server / adb.exe 其中一个，其余留空自动补齐。另有 **\[自动寻找全部]**、**\[测试并刷新]**。
3. 勾选 **记住路径**，scrcpy 目录与三个路径、启动参数、上次使用的设备会写入配置文件，下次启动直接沿用，即使 scrcpy 目录不在程序同级、或装在任意位置，也不必重新寻找。
4. 点 **\[打开配置目录]** 可在文件管理器中查看配置文件。

路径被搬走或升级换版本也不会丢：程序会记住它原来所在目录，下次启动在那附近重新找回。

> Windows 上如果 scrcpy 画面正常、但顶栏一直“无设备”：这是官方 Windows 发行包的 adb.exe 与 scrcpy.exe 同目录且不在 PATH 中的缘故，按上面的方法填/选 scrcpy 目录即可。

### 1.3 连接设备与启动画面

1. 手机开启 USB 调试并用数据线连接电脑。
2. 顶栏下拉选择设备，点 **连接控制**（建立注入通道，成功后显示绿点）。
3. 点 **启动 scrcpy**，弹出手机画面窗口。
4. 点 **截取手机屏幕**，把当前游戏画面抓进程序。
5. 配置键位与轮盘（截图取点都在抓进来的画面上进行）。
6. 按 **总开关键（默认 F8）** 开启映射；再按一次关闭。

## 2\. 界面结构与界面风格

### 2.1 默认风格

* 顶栏：设备下拉、**连接控制**、**启动 scrcpy**、scrcpy 参数框与 **...** 参数助手、顶栏「映射: 开/关」按钮、撤销/重做、关于。
* 左配置栏：scrcpy 管理、总开关键、按键组合/外观/诊断等。
* 中央四个选项卡：**键位映射**（含组合键）、**摇杆映射**、**FPS 功能**、**其他功能**，默认选中键位映射。
* **截图取点**固定在右侧主体最下方，不随键位/摇杆/FPS 内容一起滚动。

### 2.2 可视化风格

* 中央是一张**老式机械键盘外观**的标准美式全键盘（深色机身 + 灰色键帽 + 鲜明描边，含导航区与小键盘），右边是一只虚拟鼠标（左键/右键/中键/侧键/滚轮上下）。
* **点空闲键**：直接为它新建键位草稿并立刻进入截图取点；取点中该键呼吸闪烁，点操作栏的 **\[取消取点]** 可放弃（取消零残留，这一下点击也不会被记成按键）。
* **点已设置的键**：选中它（高亮 + 白描边），键盘下方出现操作栏，内容与列表编辑器完全一样（取点 / 改键 / 转长按 / 修改响应范围 / 仅 FPS / 删除等）。也可以先点 **\[取点]** 再走老流程。
* 未设置的键是半透明灰键帽 + 亮点描边，深色/浅色界面下都看得见整张键盘。
* 标签页：右侧为 **键位 / FPS 设置 / 其他功能**；左栏中部为 **键位组合 / 外观 / 诊断**（默认选中“键位组合”）。
* 两个页面的显示能力一样：键位页与 FPS 页各有一个「显示项目」多选下拉，含 **按键映射 / 组合键映射 / 永久摇杆 / 临时摇杆 / 宏 / FPS** 六项；区别只是默认值 —— 两页默认只显示键位、组合键与永久/临时摇杆，宏与 FPS 需要自己勾上（FPS 页额外默认显示“仅 FPS”键位）。FPS 页只能编辑 FPS 相关键，点到被普通映射/摇杆占用的键会给出提示。

### 2.3 风格与外观选项

|项目|可选值 / 说明|
|-|-|
|界面风格|**默认** / **可视化**。与配色是两个独立维度，任意组合都可用|
|配色|深色 / 浅色 / Nord / Catppuccin|
|控件密度|紧凑 / 标准 / 宽松|
|背景图|铺满 / 完整 / 平铺，另有暗化遮罩与面板不透明度|
|键位自动对比|默认开启。按截图逐块采样，自动决定每处键位/摇杆用深色还是浅色，并给圈描反相外套、给文字垫半透明衬底|
|键位显示亮度|在自动结果上微调（往左加深、往右变浅）；关掉自动对比后等同固定档位|

要点：

* **切换风格需要关一下再开**：风格牵动整体布局，无法像配色那样热应用。在选择器里换风格后，程序会自动关闭窗口并立刻用新风格重新打开。
* 风格与其它外观设置一起写入配置文件，**下次启动自动沿用上次选的主题**；切换按键组合也不会把主题带走。
* 老版本配置里若还写着已删除的“鸿蒙”风格，会自动按**默认**风格打开，不报配置错误。

## 3\. 键位映射

### 3.1 五种动作类型

|动作|说明|
|-|-|
|点按|按键触发一次点击。可设置触点持续时长；时长为 0 时表示按住不松手，直到再次按下同一键才抬起|
|长按|按住键盘期间手机触点保持按下，松开即抬起，实时跟随。与点按可一键互转|
|滑动|按键触发一次滑动。可分别设置起点、终点、时长、速率曲线与运动轨迹|
|系统键|注入 Android 系统按键（直接填 keycode，如返回 = 4、主页 = 3、最近任务 = 187）|
|宏|录制或设置的按键时序，绑定触发键后点一下即按顺序执行（见第 7 节）|

**点按的连点间隔**：填一个毫秒数（0 = 关闭，只点一次）。按住期间每隔这么久点一次，由本地排程一次性展开，所以每击间隔很稳；松键立刻停，不会留下“只按不抬”的触点。间隔会自动不小于单次按住时长。

要素：

* **坐标按比例保存**，换分辨率或换手机后键位自动对齐；程序不会主动改动已保存的坐标。
* **键位允许落在画面之外**，程序不做越界纠正。
* 取点 / 改键 / 修改响应范围三种交互态**互斥**，以最后一次操作为准。

### 3.2 新增与编辑键位

1. 在“新增”行选择类型（点按 / 长按 / 滑动 / 系统键）。
2. 点“未绑定”按钮，按下要绑定的物理键。
3. 按类型设置参数：点按/长按设置 x、y、响应范围（点按另有触点时长与连点间隔）；滑动分别点 **\[取起点]** 与 **\[取终点]** 在截图上取点，再设置时长、曲线、轨迹。
4. 点 **\[新增]** 加入列表。添加完成后这次操作就结束了，不会停留在取点状态。要改坐标就点该行的 **\[取点]**。
5. 已添加的键位可在行内直接修改：改写按键、调整数值、**\[取点]**、**\[转长按]/\[转点按]**、**\[修改响应范围]**、**\[删除]**。

### 3.3 响应范围

点按/长按键位有一个圆形响应范围（默认半径约 35px）。

1. 点该行的 **\[修改响应范围]**，圆圈变黄。
2. 调大小，两种都行：按 **Ctrl++ / Ctrl+-**，或**直接在截图上按住拖动**（按下处到圆心的距离就是半径）。
3. 点 **\[完成]** 退出（整段修改算一步撤销）。

修改期间 Ctrl 加减号专用于圆圈，不会缩放整个界面；退出后恢复界面缩放。

### 3.4 鼠标按键映射

可视化风格键位页的「＋ 新增按键映射」旁并列「＋ 新增鼠标按键映射」下拉，可直接选**左键 / 右键 / 中键 / 侧键1 / 侧键2 / 滚轮上滚 / 滚轮下滚**（7 项），跳过“按任意键”直接进入取点，之后与普通键位映射完全一致。鼠标左/中/右键也可以在捕获时直接按一下绑定。

> 鼠标键不能走“按任意键”那一步：按下去的同时就是在截图上点了一下，会和取点打架。

### 3.5 「仅 FPS」键位

普通键位行可勾选 **\[仅 FPS]**：勾选后该键**只在 FPS 模式生效并显示**，同键会覆盖普通映射；退出 FPS 时自动释放并恢复仍按住的普通键。支持点按、长按、滑动、系统键，以及鼠标左/右/中键、侧键和滚轮。滚轮统一映射为 BTN\_WHEEL\_UP / DOWN / LEFT / RIGHT。

### 3.6 拦截系统默认行为

Esc、F11、鼠标右键/中键/侧键/前进/后退、滚轮上下这些“本带系统功能”的键，一旦在当前配置里被绑定（且映射开启），按下会被程序截住 —— 前台窗口收不到（Esc 不再退出全屏、右键不再弹菜单），映射动作照常送进手机；没绑定、或按 F8 关了映射时一切照旧。Space / Tab / Enter / 字母数字等输入键永不拦截，随时可以打字。

### 3.7 按后延迟（防手抖连点，可选功能）

**按键、组合键、宏**三类设置都可以各设一个“按后延迟”毫秒值（默认 **0** = 不等）。整项**默认不生效**，要**两层都愿意**才真等：① 左栏「总开关键」下方的 **按后延迟总开关**（默认关闭）；② 这一条自己填的数值 **> 0**。

* 关闭总开关时整项等同于不存在 —— 各条的数值**原样保留**（随时可以再打开），逐条的数字框灰显不可改，悬停会提示去左栏打开。
* 这个开关随\*\*当前键位组合（方案）\*\*一起保存，每个方案各自一份。
* 含义是“上一次**抬起**之后再等这么久，才准下一次**按下**”，用来防止快速连点/划动时上一动作还没抬起、下一动作已经按下，两个动作在手机上互相干扰。
* 比冷却还密的输入**不会被丢弃**，而是**推迟到冷却结束再执行**。数值可设范围 0\~2000ms。
* 断开设备、关闭映射、切换按键组合时冷却表会清空，恢复连接后第一次按下永远立刻响应。

## 4\. 组合键（可选）

* 在按键映射区勾选 **\[启用组合键]** 后，组合键列表才生效；关闭时设置保留但整体变灰失效。
* 组合键采用“**前缀键**”判定：第一个键作为前缀，后续键要在前缀仍按住时按下。例如 Ctrl+R 应先按 Ctrl 再按 R。
* 前缀键有单键/功能键映射时使用 **45ms** 快速判定窗口；没有单键映射时使用 **120ms** 窗口，以降低快速组合的误触。
* 组合完成时，前缀键和成员的普通单键动作会被吞掉，不会先触发 FPS 开关或其它单键。
* 组合键的动作与普通键位一致：支持点按、长按、滑动、系统键和“仅 FPS”；点按/长按有取点，滑动有取起点/取终点/取出发点以及曲线、轨迹设置。

## 5\. 摇杆与轮盘

* **方向键**：四个方向各绑一个键（默认 WASD），支持八方向，松开自动回中。
* **取圆心**：点 **\[取圆心]** 后在截图上点一下。新建轮盘的半径固定 **150 像素**，落点自动避开已有轮盘，不会互相重叠；截图浮层上摇杆编号与列表里的“轮盘N”一一对应。

### 5.1 轮盘类型

|类型|说明|
|-|-|
|标准四向|四方向逻辑，可选“经典”或“灵敏”方向模式|
|多向轮盘|支持 2～8 个任意角度方向，每个方向一个按键；同时只接受最早按下的两个方向，双键同按时取两键方向的**中点**、推出距离仍等于影响范围|
|执行轮盘|按下方向键后手指先从圆心落下，再按设定时长快速滑到目标方向，适合“点中心 + 滑动”才能释放的技能；可调中心范围圆与滑动时长|

在标准、多向、执行之间切换时不会清空另一套方向数据。

### 5.2 半径与影响范围

* **半径**：拖“半径”数值框，或点 **\[改响应范围]** 后在截图上按住拖动（按下处到圆心的距离就是半径），也可按 **Ctrl++ / Ctrl+-** 缩放。
* **影响范围**：触点实际推出距离 = **半径 × 系数**（0.2 \~ 4.0，默认 1.0）。圈是给眼睛看的参考，系数才决定游戏里的手感。系数不等于 1.0 时，截图浮层会额外画一圈**橙色虚线**表示实际推出距离并标注像素值与倍数；点 **\[影响范围复位]** 一键回到 1.0。

### 5.3 方向模式

|模式|说明|
|-|-|
|经典（标准）|保持旧行为，同轴左右（或上下）同时按住会互相抵消|
|灵敏（后按覆盖）|同一轴最后按下的方向覆盖较早方向；后按方向先松开时，较早仍按住的方向立即恢复。左右与上下分轴计算，斜向不会互相抵消|

### 5.4 自定义终点

多向轮盘与执行轮盘的每个方向都可点 **\[设置位置]** 在截图上直接指定滑动终点（相对坐标，换分辨率/转屏后随配置自适应），可超出也可缩进基准圆；设过终点的方向显示绿色“位置:自定义”标签，点 **\[重置]** 贴回基准圆（可撤销）。截图浮层会画出圆心到终点的虚线与实心端点。方向标签统一为 上/右/下/左 或角度（例如以 45 度为一档的写法）。

### 5.5 临时轮盘

* 给轮盘设一个 **启用键** 后，该轮盘只在启用期间生效；支持“**按住启用**”与“**再按切换**”两种模式。
* 启用期间若与任何永久摇杆**共用方向键**，该键**优先归临时摇杆**（永久摇杆在该键上让位）。
* **归属切换即时生效**：松开启用键的那一瞬间，仍按着的键立刻恢复原功能（长按/系统键当场补上触点），不需要松手再按一次；按下启用键的瞬间，已经按着的方向键也会立刻推动摇杆，而不是要重按。

### 5.6 键位浮层与信息卡

* 所有键位与轮盘叠加显示在手机截图上：**绿圈 = 点按，橙圈 = 长按，黄圈 = 修改响应范围中/新增草稿，蓝线 = 滑动轨迹（内部半透明填充），青圈 = 永久摇杆，品红虚线圈 = 临时摇杆**。
* 过滤显示可按 **全部 / 仅键位 / 仅摇杆 / 永久 / 临时** 切换。
* **看方向键**：点一下截图上那个摇杆的圈，旁边会弹出信息卡（上/下/左/右四个键名，临时摇杆另加启用键与模式），再点一下或点空白处收起。画布上只标「摇杆N」，不长期压住游戏画面。
* 浮层坐标空间优先取**截图尺寸**，因此同一张截图的浮层不会因为连接控制通道、手机转屏而突然缩放或移位；若截图方向与当前触摸坐标空间不一致，画布上方会给出提示（建议重新截图后再取点）。

## 6\. FPS 瞄准与光标

FPS 功能用于把鼠标位移映射成视角转动，适合射击游戏与开放世界。设置可以**提前配置**；真正按开关键进入 FPS 模式时才会检查总映射是否已开启，避免开打前抢走 Ctrl 等快捷键。

### 6.1 基本设置

|项目|说明|
|-|-|
|拖动死区|鼠标累计位移在死区内不注入触摸移动，用于过滤手抖；越过死区后才开始移动手指|
|锚点|虚拟手指落下的起点，不是游戏准星。应取在游戏 UI 之外的干净区域；默认不自动设置，未设置时 FPS 触摸拖动保持待机并给出提示。锚点行有 **\[恢复默认]**，一键放回手机屏幕正中央（可撤销）|
|边界|有边界时触点按屏幕边缘截断，到边即停；无边界时按**单轴跑步机**工作（见下）|
|灵敏度|单位 = 设备像素 / 每个鼠标计数；实际增益 = 灵敏度 × 视角移速|
|视角移速|0.2x \~ 3.0x，默认 1.0，同时作用于触摸拖动、开放世界和虚拟手柄右摇杆|
|反转 Y|上下反转|
|归中|静止 / 阈值 / 不归中|
|按住才瞄准|可绑一个键（如鼠标右键开镜）|
|FPS 模式开关键|按它进入/退出 FPS 模式|
|按住才退出|按住期间暂时退出 FPS、恢复普通键位映射并显示系统光标，松开自动回到 FPS|

**无边界（单轴跑步机）**：以“锚点到各侧屏幕边缘的距离”与“回转半径”取小算出每侧活动带，把位移切成不越界的若干段，段间无缝抬指、立刻按回锚点接着推 —— **注入总量精确等于鼠标位移**，**触点全程不离开屏幕**（修掉了旧版“推一点、画面转头两倍”和“推到上下某个点突然不动”的问题；贴边时有效半径自动收缩为锚点到该侧边缘的距离，这是设计行为）。单次注入最多 32 跳，超出截断但每段仍在带内。

### 6.2 视角输入方式

|方式|说明|
|-|-|
|触摸拖动（通用，默认）|兼容性最好，本质是在手机屏幕上制造手指轨迹|
|虚拟手柄右摇杆（连续）|通过 scrcpy 控制通道创建 Xbox 360 兼容 HID 手柄，把鼠标位移喂给右摇杆，不产生触摸轨迹。游戏需要支持手柄右摇杆控制视角|
|虚拟手柄右摇杆（分段回中）|摇杆到达极限后保持极限一小段时间，再归中并保留超出量，模仿人类一段一段滑动视角|

> 旧版的“UHID 相对鼠标 / AOA 相对鼠标”已从界面移除，旧配置会自动迁移回触摸拖动，启动时也会清除旧的 --mouse=uhid / --mouse=aoa 参数，避免 scrcpy 自动捕获鼠标。
>
> \*\*两种虚拟手柄模式已标记废弃、不再维护\*\*（界面选项名保持原样，仍可选用）。

**触摸拖动的兼容性代价**：它本质上是在手机屏幕上制造手指轨迹，轨迹经过游戏按钮、轮盘或手势区域时可能产生副作用。请把锚点放在游戏没有 UI、不会触发缩放的干净区域；需要更适合视角转向时优先测试虚拟手柄右摇杆。

### 6.3 开放世界模式

在触摸拖动输入下不需要射击/开镜键。鼠标相对位移会映射到一条“触摸拖动带”，触点推不动时会无缝抬指/重按并接着推，因此可以无限向左/向右转向，且不会推到屏幕外被系统丢弃；水平回中半径和平滑系数可调。

### 6.4 指针消隐、钉住光标与鼠标独占

* **指针消隐**（默认开启）：触摸拖动和虚拟手柄模式下使用透明系统光标，因此即使焦点在 scrcpy 窗口也会消失；退出 FPS 或按住“按住才退出”键时会恢复光标。若程序被强制结束留下透明光标，重新启动本程序会自动恢复。
* **钉住光标**（默认开，**仅 Windows**）：FPS 瞄准期间把光标关在当前位置的 1 像素矩形里，甩枪时光标不再满屏乱跑，也不会滑到别的窗口/显示器上。只在真的瞄准时才钉；四条释放路径（退出瞄准 / 断连 / 关掉映射 / 退出程序）都已接好。开关在 FPS 页「鼠标独占与自救」分组。
* **鼠标独占（隔膜，仅 Windows）**：给鼠标盖一层“隔膜”，不让它作用到投屏窗口 —— 否则 scrcpy 窗口会收到你的点击与拖动并再转发给手机一份，同一次操作被双份输入。范围可选 **仅 FPS 模式**（默认）/ **仅投屏窗口在前台时** / **始终**，另有一个手动开关热键随时翻转、不需要重启 scrcpy。开启期间鼠标点不了任何窗口（包括本程序界面），左栏状态行会写明当前是否开启、原因、以及按哪个键关闭；关映射、断连、退出程序都会自动解除。
* 它与鼠标独占是两件事：一个管**光标**，一个管**鼠标消息**，开关互相独立。

> 鼠标独占挡不住别的程序\*\*自己注册的原始输入\*\*：若给 scrcpy 手动加了相对鼠标模式，仍会双份输入，那种情况只能用 scrcpy 侧的 --mouse=disabled 参数。

### 6.5 滚轮缩放（双指捏合）

默认开启，仅 FPS 模式生效。以锚点为中心，上滚 = 两指张开（放大）、下滚 = 两指捏合（缩小）；每齿注入一段瞬发双指手势，屏幕上不留手指、不占用你手上的触点。每齿默认 20%（5%～40% 可调），指距限制在 24px 到屏幕短边×45% 之间。生效期间滚轮会被本程序截住，不会触发前台滚动。

### 6.6 后坐力补偿（压枪）

默认关闭。开启后**按住触发键**（一般是鼠标左键）期间，按 **控制频率**（默认 60 次/秒）持续把视角向下拉，按 **控制强度**（每次向下像素，可加多档并起名）施加位移。

* **滚轮换档**：勾选后，FPS 模式内滚轮直接切换强度档（上滚往后一档、下滚往前一档、环绕），只在勾了“参与滚轮”的档之间跳；参与档不足两个时滚轮按缩放处理。
* **摇晃**：给每次控制叠加随机左右抖动（随机**打散**，不是抵消）。
* **水平补偿**（每档一套）：每档有自己的 **水平幅度**（可填负数 = 反向，0 = 该档不振荡）、**周期** 与 **波形**（正弦 / 三角），用确定的左右位移**抵消**枪口摆动；相位从按下触发键那一刻起算。每档还能各设一个 **水平 px 常量偏置**（正 = 向右）。切档时垂直强度与这整套水平参数一起切。
* **开放世界模式下只用水平 px 常量偏置、不用波形往返**（回转带会把来回摆动钳成反复抬手重按），界面按当前档有红字说明。
* **覆盖灵敏度**：触发期间替换鼠标位移的灵敏度（0 = 不覆盖）。需要配合瞄准模式使用（瞄准未激活时不生效），松开触发键立即停止。

### 6.7 卡死自愈与自救热键

真机上出现过这种状态：手碰一下手机屏，之后所有注入输入失效、只能靠按键夺回。**卡死自愈（默认开，推荐）** 会自动处理，原理两条，都**只在出问题时才动作**：

1. **手离开手机**：程序只读监听手机触摸屏，看到物理手指抬起就自动抬手重建。
2. **设备端账本对不上**：每秒只读一次设备输入状态，与本地记账对照；出现“设备端为 0 而本地还按着”或“设备端触点比本地多”就立刻重建。

“重建” = 自动做一次 **\[唤醒视角]**：只抬起此刻按着的那根瞄准指，不关映射、不退出 FPS、不改挂起/门控，下一次鼠标位移会自动重新落指。限流 300ms；宏录制/步进、绑定捕获、截图取点期间不自愈。悬浮状态行会显示「手机=摸/离 账单=N 自愈=N(原因)」这类信息。

**卡死自救（两个可绑热键，默认都未绑定）**：

1. **\[唤醒视角热键]**：只抬起我们此刻按着的那根瞄准指，不关映射、不退出 FPS。
2. **\[强制重连热键]**：等同诊断页里的 **\[强制重连控制通道]**，只重启我们自己的控制通道，不影响 scrcpy 投屏。

两个键都只认物理按键的**按下**，Windows 的按键自动重复不会连发；其处理不受鼠标隔膜影响。

## 7\. 宏

宏在独立的“宏”页面中设置，与键位映射、FPS 等功能并排。只有**可视化风格**的宏页提供自己的虚拟键盘：录制时点击虚拟键会写入步骤，非录制时点击虚拟键用于选择触发键；默认风格只保留物理键录制/设置，不显示宏虚拟键盘。

### 7.1 录制宏

* 打开录制后**按下第一个键才开始录**（在那之前不记任何东西）；记录按键的按下、抬起和时间间隔。
* 录制中即可点 **\[显示步骤]** 随时查看已录步骤，先看步骤再决定是否保存；默认只显示“事件数/约时长”的结果摘要，需要排查时打开 **\[显示录制事件]**。
* 键盘自动重复不会变成连续点击；长按会合并成一条按下和一条抬起，持续时间由两者间隔表示。
* 空闲超过用户设置时间会自动停止（最大 2000ms）。

### 7.2 设置宏

先用下拉选择“新增项目”的操作类型，再点 **\[新增操作]**；支持**按键、组合键、轮盘、FPS、点击、滑动、间隔或嵌套宏**。每条操作自带“持续”时长 —— 按下 → 持续 → 抬起，一步做完就轮到下一步（宏没有长按语义）。点击与滑动的坐标可在宏页直接 **\[取点]** 从截图上拾取。

### 7.3 草稿库与扩展宏

* **载入与取消**：载入已有宏后，**\[取消编辑]** 会清空当前草稿，不影响原宏；已录宏展开时显示只读录制步骤和时长，设置动作才可编辑。
* **草稿库**：宏页触发键行下方有「草稿库:」下拉 + **\[载入]** / **\[另存当前草稿…]** / **\[删除]**。把宏页编辑区（触发键、录制步骤、设置动作、虚拟键位层）整份存成命名草稿，**草稿允许是半成品**（可以还没有触发键）；同名要先删再存，写盘失败会回滚内存。载入会整份替换编辑区 —— 取回的是草稿，不是列表里某条已存在的宏。
* **扩展宏**：可视化风格的录制和设置区都有 **\[扩展宏...]**。窗口里可以继承已有键位组合，创建一套临时虚拟键盘/轮盘；「新增项目」可加 **＋ 按键 / ＋ 组合键 / ＋ 轮盘 / ＋ 锚点**，末尾另有**鼠标映射**下拉（左键/右键/中键/侧键1/侧键2/滚轮上滚/滚轮下滚）。弹窗内嵌截图模块，四类都能在截图上取点摆放，参数在弹窗内直接编辑；换动作类型时已取的点不丢。保存后宏按虚拟键位执行并随宏保存；点 X 或取消则完全丢弃，截图上的标识会完全还原。

  * 虚拟层里的「锚点」目前保存并保留、但回放暂不使用（弹窗内已注明）。

### 7.4 执行方式

触发键**点一下**，宏就按录制的时间线/设置步骤逐条执行 —— 录制里“按下…抬起”的间隔原样照搬。**回放忠实于当前键位设置**：例如宏里先按下“临时轮盘启用键”，其后录到的方向键会按轮盘方向重演，而不是它们平时的绑定。

宏触点与你手上的按键各用各的手指、互不顶掉；但设备总共只认十指，宏与你同时按住的触点超过上限时，多出来的宏步骤会被跳过并在界面提示（不会静默卡住）。宏触发键和普通键位一样参与“按键组合”切换：不同组合里的宏互不串用。

## 8\. 轨迹录制（滑动）

滑动动作除了取起点/终点走曲线，还可以**手绘录制一条轨迹**。

### 8.1 录制与查看

* 点 **\[● 录制轨迹]** 开始，在截图浮层上划出想要的路径（可绕圈、折返、S 形），再点 **\[■ 结束并保存]** 结束。录制**只记本程序窗口内的鼠标移动**，不干预系统鼠标。
* **录制中看得见**：浮层上实时画出你正划的那条红色轨迹，并带跳动的 **REC** 角标与「已记 N 点 / X.Xs」；划歪了随时点 **\[取消]** 或按 **Esc** 整份丢弃，原轨迹不受影响。
* **录完看得见**：截图浮层上按真实轨迹画出**折线 + 方向箭头 + 起/终点标记 + 「点数 · 像素长度」统计**，折返与绕圈一眼可辨。

### 8.2 编辑与上限

* 已有滑动的轨迹旁边有 **\[重录]** 与 **\[清除轨迹]**：清除轨迹回到“起点→终点 + 曲线”；重录重新划一遍（新轨迹保存前，旧轨迹一直有效）。
* **时间轴**：按各段距离分配总时长（距离长的段耗时多），手势的“速度感”接近录制时，而不是每段等分。
* 录制上限 **2000 点**，相邻点间距不足 4px 自动抽稀；超限后不再记（点数会停在 2000，已录部分不会丢）。
* 开遮板（蒙版）时，录制的轨迹也会画在遮板上（勾「按键映射」即显示）。

### 8.3 触发配置（录制卡片下方的「启用录制 / 开始 / 结束」）

* **启用录制**：总开关。未勾选时快捷键不触发，只有卡片上的 **\[● 录制轨迹]** 按钮能用（避免误按某个键就突然开始录制）。
* **开始 / 结束**：与宏录制共用同一套布局（0.2.1 起）。两个都填：按**开始**键开录、按**结束**键收尾；只填开始键：退回老用法，按一下开始、**再按一下结束**；只填结束键：只能用卡片按钮开始；两个都空：快捷键不触发（界面会提示，建议填一个键如 F9）。卡片上会写明“按下快捷键时，轨迹录给哪条滑动”。
* **随时可退**：录制中按 **Esc** 丢弃本次录制（原轨迹不受影响）。

## 9\. 按键组合（方案）与切换键

* 一份 profile.yaml 里可以放**多套按键组合**。每套组合的内容与行为完全一致：各自有自己的键位、摇杆、瞄准、外观设置。切换组合等于整套换车。
* 左栏 **\[按键组合 / 切换键位]** 里可以：选中哪套生效、给组合改名、**\[新建组合]**（复制当前这套并切过去）、删除组合。至少保留一套。
* **切换键位**：新增一行后点左侧按键按钮，按下目标物理键即可绑定；右侧下拉选择“切换到哪一套”。之后按一下该键，整套组合切换（按住不放只触发一次）。
* 切换键属于**功能键**（与总开关键同级）：按下它不会触发任何普通绑定。它优先于普通键位，但让位给总开关键。
* **快速切换**：支持单键或最多两键组合，可指定目标组合、正向循环或反向循环，组合键顺序无关；是否真正启用由“按键组合”页的 **\[启用快速切换]** 决定，未启用时设置仍保留。
* **参与轮换的组合可直接勾选**：在「按键组合」页每套组合右侧勾 **\[轮换]** 决定它参不参与快速切换轮换，同行还有 **\[轮换全选] / \[轮换全不选]**；一个都没勾时按切换键不换组合（0.2.1 起）。
* 切换时先抬起旧组合留下的触点与系统键，再按当前物理按键状态重建，开打中换车也不会卡键。切换键本身保存在 profile.yaml 里，上次生效的组合会在下次启动时直接沿用。

## 10\. 启动预设与常用参数

### 10.1 启动预设

点 **\[启动 scrcpy]** 按钮旁的下拉可选择预设：

|预设|说明|
|-|-|
|无|默认参数（--stay-awake）|
|2k / 4k / 1k / 720p|分辨率预设：先重置为初始参数再叠加 --max-size|
|不使用音频输出 / 使用音频输出|直接在现有参数上增删 --no-audio|

要点：

* **--max-size 是上限**：scrcpy 只缩小、不放大。设备本身能输出多高，画面上限就是多高（选了 4k 而设备只有 1080p 时，实际仍是 1080p，此时日志会给出提示）。
* 0.2.1 起，预设新增**全屏启动**与若干常用参数选项。
* 启动参数会被“记住路径”一并保存，下次启动直接沿用。

### 10.2 参数助手

参数框旁的 **...** 打开常用参数列表，含中文说明、使用示例、双击临时编辑与一键加入，附 scrcpy 官方链接。

### 10.3 自动追加的参数

* **只有虚拟手柄右摇杆模式**会在点击 **\[启动 scrcpy]** 时自动追加 --mouse=disabled --keyboard=disabled --gamepad=disabled；追加后的完整参数会立即写进上方参数框并记入日志。
* 普通触摸拖动模式不再自动修改 scrcpy 的鼠标参数，因此不会因为旧设置而自动进入鼠标捕获。
* 旧版可能把 --mouse=uhid / --mouse=aoa 保存进配置文件；本版启动时会主动清除这些旧参数并写日志提示。

## 11\. 诊断日志与排错

### 11.1 诊断面板

左栏 **\[诊断]** 面板做两件事：**告诉你现在哪里不通**，以及**把现场证据拿出来**。

* **状态自检**逐条打勾：输入捕获是否启动、有没有鼠标类设备、控制通道是否连上、映射是否开启、有没有因为触点池满而被放弃的按下。第一项打叉时下面会给一句“现在不完整，因为……”。
* **\[打开日志目录]**、**\[复制日志路径]**、**\[显示日志末尾]**、**\[导出诊断报告]**。导出会把“环境快照 + 当前配置摘要 + 日志全文”合成一个诊断报告文本文件，直接发这个文件就行。
* **诊断日志级别**：error / warn / info（默认）/ debug / trace。排查偶发问题时改成 debug 或 trace，复现一次，再看日志。改动会同时写进配置文件的 log\_level，重启后仍生效；环境变量 SCRCPY\_PAD\_LOG 优先于它。
* **引擎状态**：左栏显示“引擎: 触点 n/10 · 因触点池满被放弃 N 次”。设备端同时最多认 **10 个触点**（普通键位 + 摇杆 + 瞄准共用这一个池子），超出的按下会被设备直接丢弃，表现为“按了没反应”。这个计数不为 0 时，同时按的键少几个即可，括号里会写明是哪个键。

### 11.2 日志内容

* 日志每行包含相对启动的毫秒数、本地时间、级别、模块、线程与消息；相对时间用来分析延迟与竞态，本地时间可以直接和系统日志对齐。
* 启动时会打印**环境快照**：发行版与内核、会话类型（Wayland 还是 X11）、当前用户与所属组、配置目录与各配置文件是否存在、显示器。几乎所有“我这儿不行你那儿行”的问题，答案都在这几行里。
* 还会打印**全部输入设备的清单与判定结论**（名字、总线/厂商号、键数量、判定成键盘还是鼠标、有没有打不开的）。外接键盘不工作时，先看它在不在清单里、以及有没有在同一行给出错误码。
* 出现“**权威对账**”字样，说明底层漏掉了某个松键事件，程序已自动补发抬起防止卡键。
* 出现“**控制通道不可用: 已清空本地触点状态**”，说明通道断过；重连后按当前物理按键状态重建。
* 上一份日志如果**没有以正常退出标记结尾**，下次启动会明确提示“上次是崩溃或被强杀”；崩溃还会连线程名、出错位置与调用栈一起记下来。
* **保存日志**：可导出设备型号、Android 版本、分辨率、主机环境与运行日志。

### 11.3 常见问题速查

|现象|先看这里|
|-|-|
|提示“输入捕获不可用 / 无权限”|Linux：执行 sudo usermod -aG input $USER 后注销重登，或用 sg input 临时运行|
|连接控制失败|确认 adb devices 能看到设备，且 scrcpy-server 路径存在；在左栏手动指定 scrcpy 目录|
|Windows 上 scrcpy 画面正常但顶栏一直“无设备”|在左栏 scrcpy 管理里填/选 scrcpy 所在目录，其余会自动补齐并刷新设备|
|开了映射但按键没反应|① 顶栏「映射: 开/关」是不是被关了（日志有每次开关记录）；② 引擎状态里“被放弃”是否为 0；③ 刚在别的窗口待过一会儿的话，按一次键会自动重新确认坐标空间|
|外接键盘没反应（Linux）|打开 \[诊断] 看设备清单里有没有它；程序会定期重扫输入设备，插上后最多等约 2 秒自动接管|
|鼠标瞄准（FPS）没反应|看面板里的“生效条件自检”哪一项没通过；最常见的是尚未绑定 FPS 模式开关键。注意**触摸板不能用于瞄准**（没有相对位移轴），需要接鼠标或指点杆|
|画的圈看不清|\[外观] 里确认 **键位自动对比** 已开，再用 **键位显示亮度** 微调|
|游戏时想打字|按 F8 关闭映射即可|
|说不清原因的问题|把日志级别改成 debug 复现一次，然后导出诊断报告|

**无界面自检**：在无图形环境下验证全链路（权限 → scrcpy 定位 → adb → 控制通道 → 协议注入，注入使用无害的 hover 事件）：

```bash
./target/release/scrcpy-pad --selftest
```

## 12\. 配置文件位置与备份

默认配置目录：Linux 为 \~/.config/scrcpy-pad/，Windows 为对应用户配置目录（程序里点 **\[打开配置目录]** 可直接打开）。

|文件|内容|说明|
|-|-|-|
|profile.yaml|键位配置：多套按键组合、键位、轮盘、瞄准、切换键等|可传递、可另存的用户资产；坐标按比例保存|
|settings.json|scrcpy / server / adb 路径、启动参数、上次设备、日志级别、鼠标抓取开关、adb 命令栏等|本机私有的环境信息|
|look.json|外观缓存：配色、密度、背景图、界面风格、键位亮度等|程序自动读写，暂不提供手动编辑或单独选择|
|macro\_drafts.json|宏草稿库|与 profile.yaml 同目录|
|adb\_presets.json|手动 adb 命令的常用预设|与 profile.yaml 同目录|
|diagnostics.log|诊断日志|**每次启动整体重写**|

**配置管理**：保存、另存为、选用已有 yaml、在指定路径新建、切回默认配置、校验当前 yaml 合法性。

* **默认配置**：一键切回程序默认的配置文件（上面那个默认路径，首次运行时由程序自动创建）并加载它；该文件被删掉时会按出厂默认重新写一份。
* 路径与键位配置**分开存放**是刻意的：键位配置是可传递、可另存、可分享的用户资产，而“这台电脑上 scrcpy 装在哪”是本机私有的环境信息，混在一起会导致把配置发给别人时带上自己的绝对路径。
* 配置文件被编辑器加上 UTF-8 BOM（Windows 记事本常见）也能正常读取；真的解析不出来时会另存一份 .broken 副本并打印原因，不会静默覆盖你的配置。
* 关掉“记住路径”只是“下次启动不再使用”，**不会**清空文件里已记住的路径。

**备份建议**：要备份或迁移配置，直接复制整个配置目录即可；只想保留键位方案就单独备份 profile.yaml（可在界面上“另存为”一份 yaml），宏草稿另存 macro\_drafts.json。

## 13\. Windows 与 Linux 的差异

|项目|Windows|Linux|
|-|-|-|
|键盘/鼠标捕获|自建低级钩子（WH\_KEYBOARD\_LL / WH\_MOUSE\_LL）|evdev（读取输入设备）|
|映射时屏蔽原键（grab）|无“设备独占”原语；提供两档（默认档照常传给其它程序；独占档把已绑定键从系统默认消息里扣下），界面不显示 Linux 那种复选框|**EVIOCGRAB 设备独占**，界面显示“映射时屏蔽原键(grab)”复选框|
|文件对话框|Win32 原生|xdg-desktop-portal|
|钉住光标|支持|不支持|
|鼠标独占（隔膜）|支持|不支持（改用设备独占思路）|
|外接键盘热插拔自动重扫|无|定时重扫输入设备，拔插后自动重新接管|
|input 组权限|不需要|需要加入 input 组并重新登录|
|指针消隐|使用透明系统光标方案|触摸拖动与虚拟手柄模式下同样可隐藏指针|

> \*\*关于 Windows 的“屏蔽原键”\*\*：Windows 没有 Linux 那样的设备独占原语，本程序能做的只是把按键从系统默认消息里扣下，\*\*拦不住通过原始输入（Raw Input）读输入的程序\*\* —— 大量 PC 游戏与专业输入软件走的正是那条路。这是原理性天花板。出问题按 F8 关掉映射即立刻恢复（与 Linux 共用同一个总开关）。
>
> 鼠标独占（隔膜）管的是\*\*鼠标消息\*\*，与键盘屏蔽是两件事，开关互相独立。

## 15\. 从源码构建

```bash
git clone https://github.com/Azrl-lyh/scrcpy-pad.git
cd scrcpy-pad
cargo build --release
```

产物：target/release/scrcpy-pad（Linux）/ target/release/scrcpy-pad.exe（Windows）。之后运行项目根目录的 启动.sh（Linux）或 启动.bat（Windows）。

* 初次运行启动脚本可能会先下载依赖（约四百多条，网络畅通时约 5 分钟），首次构建约两三分钟（处理器核越多越快）。
* Linux 发布包以 **Ubuntu 20.04 / glibc 2.31 基线**构建，兼容 Ubuntu 20.04、22.04、24.04 等较新发行版；X11 与 Wayland 支持编译在同一个二进制中，运行时可自动选择会话后端。
* 启动器找不到可执行文件时会先编译，并直接使用 target/release 里的构建产物。
* 无界面自检：./target/release/scrcpy-pad --selftest。
