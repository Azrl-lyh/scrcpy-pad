## 2. 第 2 条 · 鼠标键位的专用选取 UI

新增共用助手 `mouse_key_choices()`（`app.rs`，7 项：左键 272 / 右键 273 / 中键 274 /
侧键1 275 / 侧键2 276 / 滚轮上滚 277 / 滚轮下滚 278）。键码空间沿用 `keymap::key_name` 已有命名，
不新增映射表。

- **主窗口**（可视化风格的键位页）：在 `＋ 新增按键映射` 右侧并列一个 `＋ 新增鼠标按键映射` 下拉
  （`ui_visual_keys`）。选中某个鼠标键 = **跳过"按任意键"**，直接把该键填进草稿并进入取点，
  之后与键盘那条路完全一致。
- **扩展宏弹窗**：`新增项目:` 一行末尾加 `鼠标映射` 下拉（`ui_macro_virtual_window`），
  选中后走 `assign_virtual_key(KeySlot::MacroVirtualNewBind, code)`——即与「＋ 按键」同一条路
  （建虚拟键位 → 立刻进入该虚拟键位的取点）。
- 两处都带 hover 说明，写明"其余与普通键位映射完全一样"。

## 3. 第 3 条 · 换动作类型保留已取的点

`ui_action_editor` 的动作下拉原先在 `kind` 变化时**整份重建** `Action`，坐标随之退回 (0.5, 0.5)，
表现为"取好的点被抛弃、变成屏幕中央"。现在先取出旧坐标再重建：

- `点按 ⇄ 长按`：互相带过旧 `(x, y)`（两者共用同一个落点）。
- `滑动 → 点按/长按`：用滑动的**起点**当落点。
- **切到滑动**：仍按默认几何新建（滑动是"起点+终点"两个点，不属于"一个落点"）；
  切到**系统键**没有坐标概念，维持原样。

该函数只有两个调用方（虚拟组合键行、虚拟键位行），所以改动只影响扩展宏的虚拟层。

## 4. 第 4 条 · 截图小窗

新增状态 `shot_window_open` / `shot_window_pin`（默认 false / true）。

- 用**独立视口** `show_viewport_immediate`（`ui_shot_window`）而不是 `egui::Window`：
  同进程内的 `egui::Window` 永远盖不住别的应用，只有视口能做到 `with_always_on_top`。
  调试信息悬浮窗走的也是这一套，此处不另起炉灶。
- 用一个**同一个位置、两个名字**的按钮来回切：`小窗悬浮` ⇄ `关闭小窗`；关闭即拼回下方面板，
  面板布局与加此功能之前完全一致（画布是同一个函数 `ui_shot_canvas` 画的）。
- 「置顶」勾选框出现在**两个地方**（下方面板的按钮行、小窗自己身上），驱动同一个开关：
  勾上 = `with_always_on_top()`，不勾 = 可以被其他窗口盖住。
- 小窗自带 `截取手机屏幕` 与 `+/−/重置` 缩放，与面板共用 `ui_shot_zoom_buttons`。

## 5. 第 5 条 · 截图模块拼进扩展宏弹窗

弹窗里（虚拟层清单下方、`保存到宏草稿/取消` 上方）新增「截图模块」：`截取手机屏幕` +
缩放 + `小窗悬浮/关闭小窗` + `置顶`，下面直接是截图画布（`ScrollArea::both`，最高 320px）。
原来那枚孤零零的 `截屏` 按钮从「新增项目」行删除，注释同步更正。取点提示文案改为
「请在下方截图(或小窗)上点击选点」。

一个实现细节（不然取点会**静默失效**）：`draw_overlay` 与 `assign_virtual_coord` 都从
`self.macro_virtual_editor` 取"虚拟键位表"，而这个函数开头把编辑器取成了局部变量。
所以在**正在给虚拟层取点**时，把编辑器克隆一份临时放回 `App`，画完立刻只把 `profile` 合并回来
（不取点时零成本，画的仍是实时配置）。为此给 `MacroVirtualEditor` 加了 `#[derive(Clone)]`。

弹窗同时加 `.vscroll(true)`：多了截图后内容高度会超过屏幕，允许整窗纵向滚动，
保证最下面的 `保存到宏草稿/取消` 永远够得着。

## 6. 第 6 条 · 宏草稿库（长期保存 / 自如取用）

设计取向：**一份命名列表**，与「手动 adb 命令 → 我的预设」**同一套操作**（同一个 `config_dir`、
同一个原子写 `write_atomic`），学一个会一个；不去动"给每条宏都存草稿"那种更重的方案。

- 存储：`macro_drafts.json`（`config_dir()` 下），`MacroDraft { name, key, fps_only, steps,
  instructions, virtual_profile }`——存的正是宏页编辑区那几样（`macro_page_*`）。
  草稿**允许是半成品**（可以还没有触发键），这与"新建宏"必须齐活不同。
- UI（宏页，触发键那一行下方）：`草稿库:` 下拉 + `载入` + `另存当前草稿…` + `删除`；
  点「另存」展开一行 `草稿名: [输入框] 保存 取消`（同名要先删再存，与 adb 预设同规矩）。
- 载入会整份替换编辑区，并把 `macro_loaded_index` 复位（取回的是草稿，不是列表里某条已存在的宏，
  否则按钮会显示成"取消编辑"却取消了一条不相干的宏）。
- 空草稿 / 重名 / 录制中 / 写盘失败都有明确提示，写盘失败一律**回滚内存**，不让界面和文件不一致；
  启动时读不动按空列表处理并写日志（坏文件不该让程序起不来）。

## 7. 第 7 条 · 调试信息的布局抖动

诊断出两处"弹出即顶人"的地方，都改成**固定槽位**（内容进出、位置不动；超宽单行截断，全文挂 hover）：

1. **其他功能 → 调试信息**下方那句 `正在刷新...`（以及"读取失败:…"）。刷新是每 2 秒一轮
   （`DEBUG_POLL_INTERVAL`），原来这一行每 2 秒出现一次，把下面整块「手动 adb 命令」连人带按钮
   推下去又弹回来 —— 这正是用户看到的"反复顶下方内容"。现在占用固定高度的单行槽位。
2. **顶栏的 `取消{任务}` 按钮**（随任务出现/消失、标签长短不一，会挤动右侧的 `关于` 并引起换行）。
   现在按最长的那条标签**预留固定宽度**——宽度用字体实际排版量出来，不是拍常数。
   为此把 `pending_task_label` 的全部取值收进 `PENDING_TASK_LABELS`，并在函数里加了
   `debug_assert`：以后新增一种等待标签忘了同步列表，debug 构建会当场报出来（release 无代价）。

调试信息的开关仍**只在「其他功能」里**（用户第 7 条后半句），没有在别处增加关闭入口。

## 8. 第 8 条 · 死代码

曾经的编译记录：Windows 侧 `cargo check` 零告警，WSL(Linux) 侧 5 条。逐条核实后确认
**它们只在 Linux 侧是死代码**（Windows 侧正在用），所以字面意义上的"注释掉"会直接把 Windows 构建打断。
按仓库既有写法改为**平台标注**，并在每处写明原因：

| 位置 | 告警 | 处理 |
|------|------|------|
| `capture.rs` `hook_bits_encode` | never used | `#[cfg_attr(not(windows), allow(dead_code))]` |
| `capture.rs` `hook_bits_keyboard_ok` | never used | 同上 |
| `capture.rs` `hook_bits_mouse_ok` | never used | 同上 |
| `app.rs` 自检里的 `hook_ok` 取值 | unused variable | 收进 `#[cfg(windows)]` |
| `app.rs` 自检里的 `mut checks` | unused mut | `#[cfg_attr(not(windows), allow(unused_mut))]` |
| `app.rs` `hook_ok_flag` 字段 | never read | `#[cfg_attr(not(windows), allow(dead_code))]`（字段仍要留着喂给捕获层） |

结果：**WSL 侧 5 → 0 条告警**，Windows 侧仍为 0。
