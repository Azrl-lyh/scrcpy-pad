## 1 取消按键捕获：取消即清空，且不录入当次点击（大改动 1）

### 1.1 问题

捕获按键时点右上角 **[取消按键捕获]**，这一次点击本身会被录成要绑定的触发键（实测：录成鼠标左键）；随后删掉那个键，**左键就开始触发它的功能、鼠标随之消隐**。根因是输入事件在同一帧的界面绘制**之前**处理，而"取消"按钮离捕获现场很远——用户要先找到它、再把鼠标移过去，移动与按下这两下鼠标事件都先于"取消"生效。

### 1.2 处置

| 件 | 位置 | 说明 |
| --- | --- | --- |
| 顶栏不再出现 `[取消按键捕获]` | `app.rs:2062-2071` | `pending_task_label()` 有意**不**把按键捕获列为可取消任务（连同 ①② 两条原因写在注释里）。 |
| 就地 `[取消设置]` | `app.rs:2967` `cancel_bind_button()` | 按钮摆在捕获控件**自己那一行**，按下即生效；`begin_key_capture()`（`app.rs:2424`）顺带清掉组合键捕获的半状态。 |
| 退出捕获 | `app.rs:2435` `cancel_key_capture()` | 单键与组合键捕获一起清，不留"举着等按键"的半状态。 |
| 落在取消控件上的按下整体丢弃 | `app.rs:2910` `note_cancel_zone()` / `app.rs:2929` `swallow_cancel_click()` | 每帧把"就地取消/停止控件"的矩形收集进 egui 临时存储（`app.rs:748` `cancel_zones_id()`），捕获/录制的按键处理遇到落在这些矩形里的**按下**就直接丢掉——**按取消的那一下不会被录成键、也不会被录成坐标**。 |

### 1.3 同类"录制/取点中"入口一并按同一规则处理

凡是有"取消"的录制/取点入口，取消都改成**原位**、**零残留**：

- 截图取点：[取消取点]（`app.rs:6274`、`7145`、`12770`、`12787`）——取消只清虚拟槽位/本轮草稿，不碰实时配置、不进撤销栈；
- 宏录制：[停止录制]（`app.rs:6418`）落在取消区内，停止时那一下也不入录制；
- 扩展宏弹窗：关窗（保存/取消/X 关闭）走 `app.rs:2821` 那一条收尾路径，关闭即删除列表项后截图标识**完全还原**到操作之前；
- 可视化风格虚拟键盘取键：`[取消取点]` 同样登记进取消区（`app.rs:6275`）。

> '取消'的语义统一为：**立刻清空/截断本轮已录入的数据；当次点击不入账；无残留、可逆、可预期。**

## 2 按后延迟（连点冷却，大改动 2）

### 2.1 语义（用户口径）

"**冷却**：上一次**抬起**之后再等 **30ms** 才准下一次按下。"（当初的口径，30ms 就是这个"起点值"）晚按的输入**不丢**，**推迟到冷却结束执行**；每条**各自一个数值**。

> **2026-10-10 晚追加要求：「按后延迟改为可选功能！」**，用户选定的是**"两者都要"** ——
> **总开关 + 逐条数值，两层都愿意才生效**：
> ```
> □ 按后延迟（默认关闭）
> 打开后：
>   按键 A: [按后延迟ms: 0]   ← 仍要自己填
>   按键 B: [按后延迟ms: 30]
> ```
> 于是**默认值由 30 改成 0**（不等），并新增全局开关 `Profile::tail_delay_enabled`（默认 `false`）。
> 关着的时候，整项行为与**没有这个功能时完全一致**：各条数值**原样保留**（随时可以再打开），
> 逐条数字框**灰显不可改**，悬停提示改为"去左栏打开总开关"。老配置、新建键位都不会被悄悄加上冷却。

### 2.2 数据与默认值

### 2.3 引擎（唯一的判据点）

| 件 | 位置 | 说明 |
| --- | --- | --- |
| `PressGates` 冷却表 | `engine.rs:708-743` | 每条键位/组合键一格里存"下一次按下最早可以发生的时刻"；**分条记**而不是一个全局值——给某个键设冷却不该把别的键也变钝。 |
| 读格子绝不造格子 | `engine.rs:718-721`（`PressGates::gate`） | 造出来的格子只能拿"此刻"当时刻，紧接着一比就会 `now < 此刻`，于是**任何**第一次按下都被误判成"冷却里重按"排进推迟队列。表不够长按"没冷却过"处理。 |
| 格子补 `None`、只往后推 | `engine.rs:722-730`（`PressGates::push`） | 新格子补 `None`（不受限），绝不用"此刻"填——那会把同一批补出来的其它下标一起锁住；已有格子只在 `until` 更晚时才写，不会被后来的短冷却**提前**解开。 |
| **本帧用的 `tail`** | `engine.rs:4923-4927` | `let tail = if profile.tail_delay_enabled { bind.tail_delay_ms as u64 } else { 0 };` —— 开关关着就当这条填 0。**只此一处**做这个换算，后续全部（推迟、挂冷却、宏总时长）都用它。 |
| 冷却未过 → 排 `SchedAct::Redispatch` | `engine.rs:4932-4948` | 条件是 `tail > 0 && fresh_press && now < gate`。`tail > 0` 这一条**不能省**：总开关是在**开着打**的时候被用户关掉的，表里会留着关之前挂上的冷却，只看 `now < g` 的话那些陈旧条目仍会把之后每一次按下推迟几百毫秒，而用户以为"我已经把它关了"。**冷却是否有效以此刻的 `tail` 为准，不以表里有没有残值为准。** |
| 不往表里写"空冷却" | `engine.rs:5081-5088` | `if let Some(until) = hold_until.filter(\|_\| tail > 0)`：`tail == 0`（功能没开、或这一条自己填 0）时**根本不写表**。写一个"此刻"进去虽也拦不住任何东西（`now < now` 恒假），但会让 `bind_gate()` 谎报"这条键位有冷却"，日后任何读这张表的代码都会踩坑。 |
| `redispatch_press()` | `engine.rs:5107-…` | 补发前核对：① 同一下标现在仍是**同一条键位**（用户可能在这几十毫秒里改了配置，下标位移会按到别的键上）；② 长按/系统键的触发键**此刻仍按着**（推迟期间已松手则不能再补，否则会在设备上留下"只按不抬"的触点）。补发走与正常按下**完全相同**的路径，触点池预算、宏排程、"下一次冷却"全部按正常规则重算。 |
| 收尾一起作废 | `engine.rs:2594`（`st.gates.reset()`，在 `release_all` 末尾） | 断开控制、关闭映射、切换按键组合时清空冷却表，恢复后第一次按下永远立刻响应。 |
| 组合键自己一份 | `engine.rs:4929`、`engine.rs:5086` | 组合键的按后延迟跟着组合自己走（`combo_gate` / `hold_combo`，与键位两条车道分开存）。 |

### 3.2 关键取舍：小窗倍率不能由小窗自己算

`±` 改窗口大小、窗口大小又改倍率，两者会互相追着放大（每按一次 `+` 就 ×1.44，几帧撑爆屏幕）。所以 `shot_popup_base` 是**绝对**基准，只由**屏幕/程序窗口边界**决定（`app.rs:13197` 用 `budget = area − (PAD, 抬头估算高 + PAD)`）；反过来窗口尺寸由它算出来（`app.rs:12941`，并把**实测**抬头高度加在图高上——抬头会换行、高度不是常数）。抬头高度依赖窗口宽度、而窗口宽度稳定，不构成反馈环。
