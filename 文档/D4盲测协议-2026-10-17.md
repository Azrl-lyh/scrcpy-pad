## 0. 一句话：要定什么

`aim.sensitivity_x/y` 的语义在 Raw Input 上线后变了 —— 公式是

```rust
st.ox += dx * sensitivity_x * move_speed;   // engine.rs:2815（y 同理 :2821）
```

`dx` 从**光标像素**（旧：经过 OS 指针速度/加速）变成**原始计数**（新：Raw 通道直出）。同一个数值在新语义下手感不同。本协议用**一次盲测**定出换算系数 **k**，使「新语义 × k」的观感 ≈ 「旧语义」。

## 2. 前置条件（逐条固定，否则该轮作废）

1. **同一台手机、同一方向**（2772×1280），scrcpy 参数 `--stay-awake --max-fps=120 --max-size=2560`。
2. **鼠标：`MouseSensitivity=10`、`MouseSpeed=0`（关加速）** —— 理由：旧语义的 OS 增益在加速下随速度变化（R6 实测同一注入在加速开/关下 px/事件 139 vs 14），不关掉就没有唯一解。**测完必须还原成用户常态（加速开 + 速度最右）**。
3. **显示缩放 100%**（判据用 DPI-未感知进程的 `GetSystemMetrics`=2560×1600；**`AppliedDPI` 不能当缩放探针**）。
4. **活动方案固定**（建议「🔥正常」`active:0`），**瞄准锚点 / 回转半径 / 拖动死区 / 归中参数全程不动**。
5. **游戏内**：同一张训练场或靶场、同一 FOV、同一游戏内灵敏度、同一起始站位。
6. 关掉**宏录制 / 轨迹录制 / 截图取点悬浮窗**（减少界面干扰与额外注入）。
7. 每轮任务前**手离开鼠标 2 秒**（让归中与静止判定归零）。

## 3. 设计：两臂 + 阶梯逼近 + 二次回归

### 3.1 臂 A（旧语义基准，3 轮）

legacy 二进制（`SCRCPY_PAD_NO_RAW=1`），k 不适用（它本身就是旧语义）。同任务 3 轮，取均分 **R_A**。

### 3.2 臂 B（新语义 × k，阶梯，≤6 轮）

prod 二进制（`897e0c39…`）。k 从 **1.00** 起，步长 **×1.25**：

- 本轮评分 **< R_A**（偏慢）⇒ 下一轮 `k ← k × 1.25`；
- 本轮评分 **> R_A**（偏快）⇒ 下一轮 `k ← k ÷ 1.25`；
- **同向连续两次仍未穿过 R_A** ⇒ 反向并把步长减半（×1.12）；
- **穿过 R_A** 或**走满 6 轮**即停。

> 为什么是几何步长：手感对增益近似对数敏感（×1.25 ≈ 一个"能感觉出来"的最小台阶）。

### 3.3 系数回归法（可复算）

把 B 臂的 `(x_i = ln k_i, y_i = 评分_i)` 做**最小二乘二次拟合** `y = a·x² + b·x + c`，然后：

1. 拟合优度 `R² = 1 − SS_res/SS_tot`；
2. 解 `a·x² + b·x + c = R_A`，取**落在已测区间内**的根 `k_cross`；
3. 峰值 `x* = −b/(2a)`、`k* = exp(x*)`（仅作参考，用于判断"评分是否已到顶"）。

**判据（三条全满足才算"定系数"）**

- `R² ≥ 0.5`；
- `k_cross ∈ [min k_i, max k_i]`（不许外推）；
- `|评分(k*) − R_A| ≤ 0.5`。

⇒ 输出 `k = k_cross`，保留两位有效数字，并夹在 `[0.5, 4.0]` 内。
**任一条不满足** ⇒ 判 **"未定"**，取 `|y_i − R_A|` 最小的 `k_i` 作**临时值**，并给出下次搜索区间 `[k_i/1.25, k_i×1.25]`。**不许把临时值写成"已定"。**

## 4. 每轮操作流程（Lead 与用户分工）

| 步 | 谁 | 动作 |
|---|---|---|
| 0 | Lead | 备份 `profile.yaml` / `settings.json` 并记 md5；建 `d4-blind/` 工作目录 |

| 2 | 用户 | 程序里点「**重新加载**」（配置页）；**不要打开 FPS 功能页**（那里显示灵敏度数值，会破坏盲） |

## 7. 已知偏差与风险（必须随结果一起登记，不许省略）

1. **弱盲，不是严格盲测**：程序界面仍显示「灵敏度 X/Y」与「视角移速 1.00x」，只能做到"**随机序 + 不标注 A/B**"。缓解：测试期间不打开 FPS 功能页；结束后再解封映射。
2. **两臂二进制不同**（legacy vs prod）⇒ 除 Raw 通道外可能混入其它差异。本会话已核：legacy 的 `st.raw` 恒 0、`wmin` 恒 0，其余同源（`r6_mutate.py` 单点变异 + 还原）；但**登记时必须写明"臂间差异 = Raw 通道 + 该单点变异"**。
3. **记忆漂移**：A 臂评分依赖"此刻对旧手感的记忆"，隔夜不可复现 ⇒ **两臂必须同一次运行内完成**，否则整轮作废。
4. **主观量表**：1–5 分噪声大；缓解 = 同一任务、同一场景、不看上一轮分数、每 4 轮休息。
5. **加速必须关**（§2.2）⇒ **结论只在"关加速"条件下成立**。用户日常开加速，故登记里必须写："系数在开加速时手感会不同，k 的适用条件是 OS 增益=1.0"。
6. **轮次上限 12**（3 + ≤6 + 余量）；超过即判"疲劳污染"，当天不再继续。
7. **k 的语义**：k 只对"旧→新"的换算有意义；若将来 `move_speed` 默认值变化，k 需重测（登记里写明 k 的绑定条件：**`move_speed=1.0`（🔥正常方案）**、`sensitivity=2.0`）。

## 8. 复算方法（别人怎么重算，10 行 python）

```python
import csv, math
s = {int(r["round"]): r for r in csv.DictReader(open("d4-scores.csv", encoding="utf-8"))}
m = {int(r["round"]): r for r in csv.DictReader(open("d4-sealed.csv", encoding="utf-8"))}
pts = [(math.log(float(m[i]["k"])), float(s[i]["score"])) for i in s if m[i]["arm"] == "B"]
RA  = sum(float(s[i]["score"]) for i in s if m[i]["arm"] == "A") / 3
# 最小二乘二次拟合 y = a x^2 + b x + c  → 解 a x^2 + b x + c = RA
# （正规方程 3×3；a,b,c 与 R²、k_cross、x* 一并打印）
```

脚本随结果落盘为 `d4_regress.py`，并在 `d4_result.md` 里贴出 `a,b,c,R²,k_cross,k*` 五个数 —— 任何人都能用 §8 的 10 行代码重算。
