## 用户目标

1. 修复 scrcpy 参数实际启动/报错时 GUI 信息不足的问题：完整记录命令、stdout、stderr 与退出码。

## 注意事项

- UHID/AOA 不再作为推荐或自动方案。手动往 scrcpy 参数框添加相对鼠标参数仍可能被 scrcpy 捕获鼠标，需自行承担风险。
- 触摸拖动仍会在屏幕上制造真实触点轨迹，可能触发游戏 UI/手势副作用；虚拟手柄右摇杆仅适用于支持手柄视角的游戏。
- `diagnostics.log` 每次启动整体重写，完整 scrcpy 输出可在左侧诊断面板或配置目录查看。

## 追加：虚拟手柄右摇杆模式深查与优化

- 对照 scrcpy v3.3.3 官方源码确认控制协议：`TYPE_UHID_CREATE=12`、`TYPE_UHID_INPUT=13`、`TYPE_UHID_DESTROY=14`，字段顺序与本项目 `control.rs` 一致；Xbox 360 兼容报告长度 15 字节，右摇杆位于字节 4..7，字节序为小端。
- 修正中心值：统一使用 scrcpy 的 `0x8000`（32768），避免之前 32767/32768 混用的微小偏差。
- 优化分段回中：到极限后先把极限报告保持 12ms，再发送中心，暂停 24ms 后携带超出量继续；避免 Android 把连续两次 UHID 写入合并而使游戏看不到足够转向。
- 增加虚拟手柄运行状态：界面自检显示“虚拟手柄已创建/未创建”和已发送的 UHID 输入报告数。
- 修正游戏手柄模式的自检逻辑：不再错误要求设置触摸锚点；游戏手柄模式提示游戏必须支持手柄右摇杆视角。
- 增加创建/销毁虚拟手柄的诊断日志，便于在 `diagnostics.log` 中确认设备端是否接受 UHID 控制消息。
- 回归：79 个单元测试全部通过；Windows 与 Ubuntu 20.04/glibc 2.31 Linux 发布包已重新构建。

- `Aim` 增加 `move_speed`（0.2x-3.0x，默认 1.0x），统一作用于触摸拖动、开放世界与虚拟手柄右摇杆。

- 其他功能新增调试信息：手机帧率/刷新率与手机分辨率，支持手动刷新和约每秒自动刷新，并可用置顶悬浮小窗口覆盖在 scrcpy 窗口上方查看。
- 帧率读取优先使用 `dumpsys SurfaceFlinger --latency` 的刷新周期，回退到 `dumpsys display`；分辨率使用现有当前显示坐标空间查询。
- 验证：`cargo fmt --all -- --check` 通过，81 个单元测试全部通过；Windows 与 Ubuntu 20.04 / glibc 2.31 Linux 发布包均已重新构建。

## 追加：Windows 触摸板异常的排查与退出清理

- 代码审计结果：程序没有修改 Windows 触摸板驱动设置、注册表或鼠标加速参数；唯一会修改的全局系统状态是 FPS 指针消隐时替换系统光标方案。
- 修复退出清理：Windows 低层键鼠钩子线程现在会在进程退出前收到退出消息，并有界等待 `UnhookWindowsHookEx` 完成，避免钩子拖到进程退出阶段才被系统异步回收。
- 主程序在 `run_native` 返回后再次兜底执行 `SPI_SETCURSORS` 和箭头光标恢复；启动时也会修复上次异常退出可能留下的透明系统光标。
- 新增恢复系统光标失败的诊断日志，便于区分“光标方案残留”和触摸板驱动/系统设置问题。
- 验证：关闭主窗口后进程可立即退出；`cargo fmt --all -- --check`、`cargo check` 和 81 个单元测试全部通过；Windows 与 Ubuntu 20.04 / glibc 2.31 Linux 发布包已重新构建。
