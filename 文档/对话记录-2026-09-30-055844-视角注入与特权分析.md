## 一、鸿蒙 PC 映射无响应的真正根因

### 根因

`HdcShell` 启动的是交互式：

```text
hdc -t <serial> shell
```

然后向该进程 stdin 写 `uinput` 命令。当前 Huawei HDC 明确输出：

```text
Not support stdio TTY mode
```

因此 shell 进程虽然存在，`send()` 也返回成功，但命令实际上没有执行。测试页使用单次 `hdc shell <command>`，所以测试有反应、映射无反应。

### 修复

- `HdcInputBackend` 不再使用交互 stdin。
- 每条输入命令直接调用一次真实的 `hdc shell ... uinput ...`。
- 该路径与测试页已验证可用的路径完全一致。
- `send()` 失败时会向 stderr 打印 `[hdc-input]` 错误，避免静默失败。
- 新增诊断命令：
  - `map-smoke <serial>`：验证 `MappingRuntime -> HdcInputBackend -> uinput`。
  - `map-live <serial> [seconds]`：启动全局捕获并等待真实按键。

### 真机验证

实际执行 `map-smoke` 成功。随后用 GUI 自动启动路径和真实 W 键做端到端验证，trace 中出现：

```text
[hdc-input] uinput -T -d 244 2195
[hdc-input] uinput -T -m 244 2195 244 2025 0
[hdc-input] uinput -T -u 244 2025
```

证明：

```text
Windows 全局键盘捕获
  -> MappingRuntime
  -> HdcInputBackend
  -> hdc shell
  -> uinput
```

已经能够工作。

## 二、Windows 指针消隐修复过程

### 错误方案

最初使用 `ShowCursor(FALSE)` / `SetCursor(NULL)`。现象是：

- 本程序窗口有焦点时指针会消失。
- 焦点切到 scrcpy 后，scrcpy 重新绘制自己的光标，指针再次出现。

原因是 `ShowCursor` 对可见窗口线程有依赖，后台捕获线程调用不能可靠覆盖 scrcpy 窗口。

### 当前方案

Windows 下改为系统级透明光标：

- `CreateCursor` 创建透明单色光标。
- `SetSystemCursor` 替换常用 `OCR_*` 系统光标，包括普通箭头、I 形、等待、十字、调整大小、禁止、手形等。
- 因此焦点在 scrcpy 或其他窗口时，系统提供的仍是透明光标。
- 退出捕获时调用 `SystemParametersInfo(SPI_SETCURSORS, ...)` 恢复系统光标方案。
- 程序启动时主动恢复一次，修复上次异常退出可能残留的透明系统光标。
- 捕获期间 GUI 线程每帧补 `SetCursor(NULL)`，防止本窗口绘制时重新显示箭头。

主程序和 `harmonyos-pc` 的 Windows 捕获层都已同步使用该系统级方案。

## 三、视角模式与开放世界模式

### FPS 专用键

普通键位行的 `仅 FPS` 复选框已经存在并已重新构建：

- 勾选后只在 FPS/视角模式运行期间生效并显示。
- 同物理键的 FPS 专用映射优先于普通映射。
- 退出 FPS 或“按住才退出”时释放 FPS 触点，恢复普通映射。

### 开放世界模式

`Aim` 新增字段：

```text
open_world
open_world_radius
open_world_smoothing
```

触摸拖动实现：

- 鼠标相对位移映射为手指拖动。
- 水平方向在锚点附近维持一条拖动带。
- 越过回中半径时抬指、回锚点重按，并保留超出量继续同方向移动。
- 因此可无限向左/向右转。
- 平滑系数和水平回中半径可调。

视角设置现在可以在映射开启前提前配置；真正按开关键进入模式时才检查总映射是否开启，避免开映射前按 Ctrl 等键被抢走。

### 视角输入模式

新增枚举 `ViewInputMode`：

```text
touch_drag
uhid_mouse
aoa_mouse
```

当前 GUI 常规列表只保留：

```text
触摸拖动（通用）
UHID 相对鼠标（推荐）
```

AOA 保留兼容字段，但从常规列表中移除，且不再自动添加到 scrcpy 参数。

## 四、UHID/AOA 源码研究结论

查阅了 scrcpy 源码和文档：

```text
app/src/uhid/mouse_uhid.c
app/src/hid/hid_mouse.c
app/src/control_msg.h
server/.../UhidManager.java
doc/mouse.md
```

结论：

1. `--mouse=uhid` 创建的是标准相对 HID 鼠标。
2. `mouse_uhid.c` 中 `relative_mode = true`，发送相对 `dx/dy`。
3. `process_touch = NULL`，UHID 鼠标不产生触摸事件。
4. Android 通常把它显示为鼠标指针；只有支持鼠标视角 / pointer capture / GenericMotion 相对轴的游戏才可能用于镜头。
5. `--mouse=aoa` 是 USB OTG 级 HID，通常不能与 ADB/USB 调试同时占用 USB，不适合常规 scrcpy 投屏 + 映射。

### 当前 UHID 参数处理

当用户选择 `UHID 相对鼠标` 并点击 `启动 scrcpy`：

- 程序会把以下参数明确写入可见的 scrcpy 参数框：

```text
--mouse=uhid --keyboard=disabled
```

- `--keyboard=disabled` 用于避免 scrcpy 和本程序同时注入键盘。
- 如果鼠标被 scrcpy 捕获，按 scrcpy 默认 `Alt` 快捷键交还。
- AOA 不自动添加，文档说明其 OTG/USB 独占限制。

已新增单元测试，验证 UHID 参数只追加一次，AOA 不会被自动修改。

## 五、组合键支持

新增可选组合键，开关位于“按键映射”区。关闭时组合键列表保留但整体变灰失效。

当前实现是前缀键模型：

- 第一个键是前缀，例如 `Ctrl+R` 先按 Ctrl、再按 R。
- 前缀有单键/功能键映射时使用 45ms 快速判定窗口。
- 前缀没有单键动作时使用 120ms 窗口。
- 组合完成时吞掉组件单键，避免先触发 FPS 开关等动作。
- 支持点按、长按、滑动、系统键。
- 组合触点使用独立 lane/PID，并纳入设备 10 触点预算。

## 六、关于设备端特权与辅助程序的可行性分析

### 结论

如果游戏支持鼠标视角或手柄右摇杆视角，那么“电脑端 + 设备端特权助手”很可能可以做到接近原生、平滑、无触摸副作用。

如果游戏只接受触摸拖动来控制镜头，则即使有特权，也没有通用方法完全绕过触摸语义。

### 可行架构

```text
电脑端 scrcpy-pad
  鼠标/键盘/手柄捕获
  全局光标隐藏
        |
        | adb forward / hdc fport / 本地 socket
        v
设备端 Helper
  - 虚拟相对鼠标
  - 虚拟手柄
  - 虚拟触摸屏
        |
        v
Android/HarmonyOS InputManager / UHID
```

### 特权层级

1. 普通 App
   - 只能无障碍手势、悬浮窗、转发输入。
   - 无法创建任意虚拟 HID，也难持续注入相对鼠标。

2. ADB/HDC shell 助手
   - 可运行 `app_process` 或 native helper。
   - Android 上可考虑 UHID 虚拟鼠标/手柄。
   - HarmonyOS 上需验证 `/dev/uhid`、`/dev/uinput`、`uinput` 的 shell 权限。

3. Root / 系统签名 / 系统特权
   - Android：可创建虚拟 HID、使用 `InputManager.injectInputEvent`、精确控制 pointerId。
   - HarmonyOS：可考虑 `OH_Input_RequestInjection`、`InjectMouseEvent`、`InjectTouchEvent`。
   - 通常需要系统签名、ACL 或白名单；华为零售机获得难度很高。

### 仍然无法解决的问题

如果游戏只认触摸：

- 最终仍必须注入 `ACTION_DOWN/MOVE/UP`。
- 触点落在按键、轮盘或手势区域时，游戏仍可能响应。
- 没有通用的“这个触摸只给镜头、不给 UI”的 Android/HarmonyOS 公共标记。
- 特权只能让注入更低延迟、更易管理、支持更多 pointerId 和更好的安全区域策略。

## 九、虚拟手柄右摇杆视角实现（2026-09-30 14:05:33 +08:00）

用户要求：只为 Android 主程序实现“虚拟手柄右摇杆视角”，先备份，再开始大改。

备份：

```text
备份/scrcpy-pad-before-virtual-gamepad-20260930-134821.zip
```

### scrcpy 协议依据

从 scrcpy master 源码确认：

- `app/src/uhid/gamepad_uhid.c` 通过 `SC_CONTROL_MSG_TYPE_UHID_CREATE/INPUT` 创建并更新 HID 游戏手柄。
- `app/src/hid/hid_gamepad.c` 定义标准 Xbox 360 兼容 report descriptor。
- Gamepad 输入 report 固定 15 字节：
  - 0-3：左摇杆 X/Y
  - 4-7：右摇杆 X/Y
  - 8-11：L2/R2
  - 12-13：16 个按钮
  - 14：DPAD hat
- 游戏手柄 HID id 从 3 开始；本项目使用 id=3。

### 代码实现

1. `src/control.rs`
   - 新增 UHID_CREATE / UHID_INPUT / UHID_DESTROY 序列化。
   - 加入 scrcpy 的完整 Xbox 360 HID report descriptor（80 bytes）。
   - 增加 UHID create/input/destroy 客户端方法。
   - 单元测试锁定 create/input 字节布局。

2. `ViewInputMode`
   - 新增：
     - `virtual_gamepad_continuous`
     - `virtual_gamepad_segmented`
   - 原 `touch_drag`、`uhid_mouse`、`aoa_mouse` 保留。

3. `MappingRuntime`
   - 新增 `GamepadState`。
   - 使用右摇杆 X/Y 轴。
   - 鼠标相对位移经过灵敏度缩放后写入右摇杆。
   - 连续模式：摇杆保持偏转，鼠标停止一段时间后自动回中。
   - 分段回中模式：摇杆到达极限后发送极限值 -> 发送中心 -> 暂停 24ms -> 携带超出量继续发送，实现人类分段滑屏式的视角移动。
   - 切换为非手柄模式、关闭映射、断开控制通道时会发送回中并销毁虚拟手柄。

4. GUI
   - `视角输入`新增两个虚拟手柄选项。
   - 虚拟手柄模式启动 scrcpy 窗口时写入 `--mouse=disabled --keyboard=disabled --gamepad=disabled`，避免可见 scrcpy 窗口和映射程序同时创建/注入输入。
   - 虚拟手柄通过本项目自己的 control-only scrcpy-server 控制通道创建，不依赖 scrcpy 窗口的物理手柄转发。
