## 工具与编码

- 当前是 PowerShell 5.1，不支持 `cmd1 && cmd2`。用分步命令、`;` 或显式检查 `$LASTEXITCODE`。
- PowerShell 5.1 读取无 BOM 的 UTF-8 `.ps1` 会按 ANSI 处理，中文会乱码并导致语法错误。`release/build.ps1` 必须保存为 **UTF-8 with BOM**。
- 终端显示中文乱码时不要立刻改代码；先确认文件编码和执行 shell 的编码。
- 不要用多个 bash 风格的 `<<'PATCH'` here-doc 拼在一条 PowerShell 命令里。用单独的 `apply_patch`，或先创建脚本文件再执行。
- `New-Item -LiteralPath` 在当前 PowerShell 5.1 不可靠；目录创建用 `New-Item -Path ... -Force` 或 `[IO.Directory]::CreateDirectory()`。
- 读取源码/文档优先显式 `-Encoding utf8`；涉及 PowerShell 脚本时注意 BOM。

## 文件删除与路径安全

- 递归删除前先解析绝对路径，确认路径位于 `D:\GitHub\scrcpy-pad-developing-yaml` 内。
- 不要用 `Remove-Item -Recurse -Force` 配合后台拼接路径；工具策略可能拦截，且不安全。优先显式绝对路径、`-Recurse`、必要时单独处理 `-Force`。
- 不要把 PowerShell 路径交给 `cmd /c`、批处理或另一个 shell 做删除/移动。
- Windows 与 WSL 分隔符不同：Windows 用 `\`，WSL 用 `/`；WSL 挂载盘符必须是小写，例如 `D:\GitHub\foo` -> `/mnt/d/GitHub/foo`。
- 不要直接把原始 Windows 路径传给 `wsl.exe` 再交给 `wslpath`；`wsl.exe` 可能吞掉反斜杠。当前约定是手动转换盘符路径。
- `wsl.exe -l -q` 输出是 UTF-16/带 NUL，读取后要清掉 NUL 并 `Trim()`。
- 构建/打包前检查 `Get-Process scrcpy-pad`；运行中的 `release\windows-x86_64\scrcpy-pad.exe` 会锁住文件，导致覆盖失败。

## 构建与发布

- Windows `cargo build --release` 产出在 `target\release\`；Linux WSL 构建产出在 `target-linux-glibc231/release/`。
- `release/build.ps1 -Target all` 默认先构建 Windows，再通过 WSL `Ubuntu-20.04` 构建 Linux；`build.bat` 无参数默认也是 all。
- `release/build.sh` 默认 `all`；只做单平台时显式传 `linux` 或 `windows`。
- WSL bash 默认 PATH 找不到 cargo；必须把 `/home/azrl2004/.cargo/bin` 放进 `PATH`。
- Linux 产物必须检查 glibc 上限；当前目标基线是 `2.31`，最近一次实测最高 `GLIBC_2.30`。
- `target*` 是构建缓存，不是发布物；清理时只保留当前需要的缓存，历史版本放 `release/history/`，不要重复保留解压目录。
- 当前约定：用户没有明确要求时，不要提交 Git；只改本地工作树。

## 快速开工检查

1. `pwd` 是否为仓库根目录。
2. 是否有运行中的 `scrcpy-pad`。
3. 当前 shell 是 PowerShell 5.1 还是 WSL bash。
4. 需要 Windows 还是 Linux 产物的路径和 glibc 基线。
5. 递归删除/移动的绝对路径是否都在仓库内。
6. 若写 `.ps1`，保存为 UTF-8 with BOM。

## 风味要求（用户要求）

- 有始必有终：只要提供了“开始/载入/进入/添加”等选择，就必须提供对应的“停止/取消/退出/清除”。
- 用户有最大选择权：既然给了选择，就要给“不选择”的选择；取消必须无残留、可逆、可预期。
