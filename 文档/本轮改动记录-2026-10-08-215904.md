## 1. R1 · 临时摇杆抢占普通摇杆键位

### 1.1 语义

优先级链在本仓库原来是「① 临时轮盘启用键（永远吃掉）→ ② 已啮合轮盘的方向键 → ③ 普通绑定」。
问题是 ② 这一段**没区分轮盘是临时的还是永久的**：临时摇杆启用后如果和某个永久摇杆
共用一个键，两者会同时响应（或按遍历顺序抢，结果不确定）。

本轮把 ② 补齐为：**已生效的临时轮盘对任意键位有抢占优先级**；被抢的永久轮盘在该键上让位。
临时轮盘停用后，键位**当场**交还——引擎侧因为方向状态是从物理键镜像推出来的，自动就接上了；
宏侧是排出来的，因此显式补了一次"继任者接手"（见 §1.3）。

### 1.2 引擎路径（`src/engine.rs`）

- 新增**纯函数** `wheel_dir_wanted`（engine.rs:779）——把"某方向键此刻该不该生效"的完整判定抽出来：

  ```rust
  engaged && held && (is_temp || !key_taken_by_active_temp_wheel(profile, wheels, code))
  ```

  抽出来的原因是 `reconcile_wheels` 需要 `&mut [WheelState]`（要写回 `pressed`），
  闭包捕获 `wheels` 会同时借用两遍。拆成不吃 `&mut` 的普通函数后，`reconcile_wheels`
  与单测都调它，规则只有一份。
- `reconcile_wheels`（engine.rs:655）两个分支（`Standard` 用 `[up,down,left,right]`、
  `Custom` 用 `active_dirs()`）都改成先算 `let engaged = w.temp.is_none() || wheels[j].active;`
  再调 `wheel_dir_wanted(...)`。
- 既有谓词 `key_taken_by_active_temp_wheel`（engine.rs:766）与
  `macro_key_taken_by_active_temp_wheel`（engine.rs:793）沿用，前者是引擎侧判定。
- `dispatch_input` 的 ② 段（engine.rs:3786 起）用 `temp_taken` 把抢占先于普通绑定落地。

### 1.3 宏路径（`src/engine.rs`）

宏回放的状态是**排出来的**（`MacroResolve` + `MacroPending`），不像引擎那样能从物理键现推，所以：

- `emit_step_press`（engine.rs:4990）② 段加 `temp_taken`（engine.rs:5031）。
- `macro_wheel_transition`（engine.rs:5123）的**停用分支**新增「继任者接手」：
  临时轮盘停用时，先在 `pending` 里把它挂在这个键上的部分抬掉；若 `pending` 里已没人挂这个键，
  再扫一遍 `vp.wheels`，把**仍然生效、键也还按着的**永久轮盘的方向重新按下去
  （engine.rs:5213–5250 附近的 `heirs` 段）。

### 1.4 新增单测（2 条）

- `active_temp_wheel_preempts_a_permanent_wheel_on_the_shared_key`（engine.rs:7369）
  ——永久轮盘右=37 vs 临时轮盘（Hold，启用键 18）下=37；逐段断言 ①/②/③、
  未共享的键 17 不受影响、启用键本身也被抢的情形、以及临时 vs 临时两者都响应。
- `macro_temp_wheel_takes_over_and_hands_back_the_shared_key`（engine.rs:8604）
  ——永久 + 临时轮盘共用 `up: 17`，临时启用键 Z=90（Hold），另在 17 上挂一个 Hold 绑定做探针。
  断言键序列为「临时占 W → 抬起 → 永久当场接手 → 抬起」，且 `clicks == 0`
  （W 全程归摇杆，一次都不许落回普通绑定）。

## 2. R2 · 轮盘落点画成圆圈（预留可调接口）

- 新增函数 `wheel_dir_end_radius_px(m, w, scale)`（app.rs:12647）：

  ```rust
  let push_px = w.push_px(m) * scale;
  let key_px  = m.len(crate::keymap::DEFAULT_RADIUS) * scale;
  push_px.min(key_px).max(1.0)
  ```

- **为什么取 min（而不是 max）**：`push_px` 可以很大——半径 300px × 影响范围 4 = 1200px。
  取 max 会让落点圆在屏幕上"糊成一片"，而用户要的语义是「圆圈大小 = 手指影响范围 = 按键大小」，
  即视觉上要和截图上的键位圈同一个尺度。取小既能表达"手指接触面"，又不会遮挡画面。
  这一点已经写在函数上方的注释里，包括用户拍板的「现固定，未来可调」。
- **预留接口**：`wheel_dir_end_radius_px` 本身就是那个"size/半径接口"。将来要做
  「落点圆圈大小」设置，只需在这里加入参（或在 `WheelDirection` 上加 `end_radius: Option<f32>`），
  全链路（浮层标注、信息卡、以及将来任何画落点的地方）都只改这一处。
  注释里明确写了「别再在别处直接写圆点/写死半径」。
- 落点由"圆点"改为"圆圈"后，视觉半径与截图键位圈一致，用户可直接目测影响范围。

## 3. R3 · 「多向轮盘」（改显示名，零语义改动）

- `WheelKind::label()`（keymap.rs:732 附近）：

  ```rust
  Self::Standard => "标准四向",
  Self::Custom   => "多向轮盘",   // 旧显示名「自定义方向」
  Self::Execute  => "执行轮盘",
  ```

- **`WheelKind` 枚举本身没动**，YAML 取值仍是 `custom` → 旧配置一字不用改、行为一字未改。
  用户口径原文：「就是它，只是改个名」。
- 在 `WheelKind` 上方补了大段文档注释（keymap.rs:703 起），说明为什么 `Custom` 就是「多向轮盘」：
  - **效果≈执行轮盘**：方向集合一样——任意 2–8 个方向、每个方向可设任意角度、
    还能点「设置位置」在截图上直接指定终点；方向键落点走同一套 `wheel_combo_offset`
    （双键取两键方向的中点、距离规整到基准圆）。
  - **行为=普通轮盘**：按下方向键后触点**一直推在目标上**（长久指引），松开才回中/抬指；
    **不是**执行轮盘那种「按下→拖动到目标→撤去」的一次性手势。
  - 于是与 `Execute` 的差别只在"撤不撤"：`Execute` 每次按下跑一段中心→目标的插值滑动然后抬手
    （快慢由 `execute_direction_ms` 决定），`Custom` 把触点停在目标上等你松手。
- `active_dirs` / `ensure_custom_directions` 的注释同步说明了这层等价关系。

## 4. R4 · 扩展宏弹窗（四类新增 + 截屏 + 无残留）

### 4.1 强复用路线（不另起炉灶）

弹窗里**没有**把主画布/主控件搬进来，而是复用同一条交互链：

- 「取点」仍然走**同一个** `picking: Option<CoordSlot>`；
- 「取键」仍然走**同一个** `waiting_key: Option<KeySlot>`；
- 弹窗里的行都是**纯函数**（只读写弹窗自己那份虚拟键位表，不碰 `Shared`、不碰 `App`），
  需要 `&mut App` 的动作回抛成 `MacroVirtualAct`，由 `App::apply_virtual_act` 统一落地。
  好处：①弹窗里那套控件永远改不到实时配置；②与主界面共用一套取点/取键交互；③关窗时把请求列表一丢就干净了。

### 4.2 新增的数据结构（`src/app.rs`）

- `KeySlot` 新增 4 个变体：`MacroVirtualNewBind`、`MacroVirtualComboKey{combo,slot}`、
  `MacroVirtualWheelDir{wheel,dir}`、`MacroVirtualWheelEnable(usize)`；
  加 `KeySlot::is_virtual()`（app.rs:297），用于关窗/取消/删除目标时把这些"待完成操作"清掉
  ——否则虚拟键盘会一直举着「按任意键…」，用户按下的键写进一个已经不存在的弹窗。
- `CoordSlot::MacroVirtual(MacroVirtualPick)` + `CoordSlot::is_virtual()`（app.rs:355）。
- `enum MacroVirtualPick`（app.rs:364）= 四类取点目标：`Bind / Combo / WheelCenter / AimAnchor`。
  存成"哪一类 + 第几个"而不是堆下标，是为了删除列表项之后剩下的索引仍然自洽
  （`assign_virtual_coord` 取不到就什么都不做）。
- `enum MacroVirtualAct`（app.rs:385）= 回抛的动作：`PickBind / PickComboPoint / PickWheelCenter /
  PickAimAnchor / TakeKey / RemoveCombo / RemoveWheel`。

### 4.3 落地函数

| 函数 | 位置 | 作用 |
|------|------|------|
| `assign_virtual_coord` | app.rs:2342 | 把取到的 (x,y) 写进**弹窗那份**虚拟键位表（按键点按/长按、组合键、轮盘圆心、描点锚点）；日志「扩展宏虚拟键位坐标已设置: (x, y)」；**不推 undo** |
| `assign_virtual_key` | app.rs:2391 | 虚拟键盘取键：新建按键 → 建/选按键并立刻 `begin_pick(...)`；组合键成员；轮盘方向键；轮盘启用键 |
| `apply_virtual_act` | app.rs:2469 | 统一落地上面的 `MacroVirtualAct`；删除项时顺带 `clear_virtual_pick()` |

在 `assign_key` / `assign_coord` 的开头各加一个短路分支：虚拟槽位直接分流到上面两个函数，
**不 push undo、不写实时配置**。

### 4.5 「不留键位垃圾」是怎么做到的（用户明确要求）

结构性保证，不靠"记得清干净"：

1. 虚拟层的浮层**只在** `picking.is_virtual()` 且编辑窗还活着时才绘制；
2. 虚拟取点**从不**写进实时配置、**从不**进 undo 栈；
3. 队列里的动作只在弹窗保持打开时应用；
4. 保存 / 取消 / X 关闭 /「取消取点」/「取消选键」/ 删除列表项，全部走 `clear_virtual_pick()`；
5. 实时草稿标记用 `!virtual_src` 门控 —— 虚拟取点期间不画实时草稿的落点/连线。

`draw_overlay`（app.rs:8232）里的切换（app.rs:8256–8262）：

```rust
let virtual_src = self.picking.map(CoordSlot::is_virtual).unwrap_or(false);
let virtual_editor = if virtual_src { self.macro_virtual_editor.as_ref() } else { None };
let src: &Profile = match virtual_editor { Some(e) => &e.profile, None => &g.profile };
```

之后按键 / 组合键 / 描点 / 轮盘四段都改读 `src`；宏步骤一段**显式保留**在 `g.profile` 上（有注释）。
离开取点态的那一帧，`src` 立刻回到实时配置 —— 截图上的标识回到操作之前的样子。

### 7.1【高·已修】R1 在宏回放里只做了一半：临时摇杆"启用瞬间"不抢占永久摇杆

- 位置：`macro_wheel_transition` 的**启用分支**（`src/engine.rs:5152` 起，`pending.remove(&key)`
  命中 `MacroPending::Wheel { parts }` 的那个 arm）。
- 缺陷：该 arm 只把临时轮盘 `j` 的 part **加进** `parts`，**从不移除**被抢占的永久轮盘的 part，
  也不补发它的 `down:false`。结果两把轮盘同时排了 `SchedAct::MacroWheel{down:true}`，
  运行期两个触点一起推——正是 R1 要消灭的情形。原注释里"先抬掉它此刻挂着的动作
  （普通绑定/系统键/**别的形态**）"对"另一把轮盘"这一形态是**假的**。
- 为什么 215 全绿也漏掉了：原有两条临时轮盘测试分别是"先按启用键、后按方向键"
  和"按住的是**普通绑定**"，**没有一条**覆盖"方向键已被永久轮盘按着、随后才启用临时轮盘"。
- **修复**（`src/engine.rs:5152` 起）：在启用分支里遍历 `parts`，把 `wj != j` 且
  `vp.wheels[wj].temp.is_none()`（即**被抢占的永久轮盘**）的部件当场 `down:false` 抬掉，
  其余保留；然后才按 `j`。临时轮盘之间不互相抢占（与
  `macro_key_taken_by_active_temp_wheel` 同口径），所以只对永久轮盘动手。
