## 已解决的真机连接问题

初始状态：

```text
4CY9K25628041938 USB Offline
```

HDC 日志根因：

```text
Cannot mkdir 'C:\Users\36124\.harmony\'
get key path failed
load public key failed
```

原因是 HDC 主机端无法创建用户密钥目录，手机端因此没有收到正确公钥，也不会弹出 USB 调试授权。

修复方式：

1. 创建 `C:\Users\36124\.harmony`
2. 让 DevEco HDC 自己生成原生 PEM 密钥：
   - `hdckey`
   - `hdckey.pub`
3. 重启 HDC
4. 设备状态变为 `Unauthorized`
5. 用户在手机上确认 USB 调试授权
6. 状态变为 `Connected`

1. FPS 专用键覆盖普通键

## 映射启动后无反应修复（2026-09-30 00:22:34 +08:00）

用户反馈：鸿蒙 PC 端点击启动映射后按键无反应，只有设备测试按钮有反应。

根因：

- `MappingService::start` 启动全局捕获后，`MappingRuntime.enabled` 仍保持默认 `false`。
- GUI 文案只说“启动全局键盘捕获”，用户会理解为已经开启，但实际还必须再点一次“开启映射”或按 F8。
- 测试页不使用 `MappingRuntime`，而是直接调用单次 HDC 输入命令，因此始终有反应。

修复：

- `启动全局键盘捕获` 改为 `启动并开启映射`。
- 服务启动成功后立即调用 `MappingRuntime::set_enabled(true)` 并同步指针状态。
- 状态栏明确显示“映射已开启，按键即可控制手机；F8 可暂时关闭”。

验证：

## 鸿蒙映射无响应的真正根因（2026-09-30 04:21:01 +08:00）

进一步用真机 HDC 复现后确认：

- `HdcShell` 启动的是 `hdc -t <serial> shell` 交互式 shell，然后把命令写入 stdin。
- 当前 Huawei HDC 明确输出：`Not support stdio TTY mode`。
- 因此 shell 进程虽然存活，`HdcInputBackend::send` 也返回成功，但命令实际上没有执行。
- 测试页走的是单次 `hdc shell <command>`，不经过这条错误的常驻 shell，所以测试有反应、映射无反应。

修复：

- `HdcInputBackend` 不再使用伪常驻交互 shell，改为每条 `uinput` 命令调用一次真实 `hdc shell`。
- 该路径与已验证可用的测试页完全相同。
- 真机执行 `tap-fast` 成功返回，确认新路径可执行。
- 新增 `map-smoke <serial>` 诊断命令；真机执行成功，完整经过
  `MappingRuntime -> HdcInputBackend -> hdc shell -> uinput`，确认映射运行时链路可注入。
- 新增 `map-live <serial> [seconds]` 诊断命令并做了端到端真机测试：启动全局捕获后从另一进程发送 W
  键，trace 中实际出现 `uinput -T -d`、`-m`、`-u` 三条命令，确认“全局捕获 -> MappingRuntime -> HDC”整条链路工作。
- 又用 `SCRCPY_PAD_HDC_AUTOSTART=1` 启动实际 GUI，并在 GUI 自动开启映射后发送 W；trace 再次出现
  `uinput -T -d/-m/-u`，确认用户实际点击“启动并开启映射”的同一条 GUI 代码路径也已工作。
- 文档明确记录：高实时目标后续应评估 `hdc fport` + 设备端辅助 HAP，而不是继续依赖 HDC 交互 stdin。

## 主程序视角/组合键/Windows 指针消隐改动（2026-09-30 04:29:09 +08:00）

1. Windows 指针消隐加固
   - `ShowCursor` 可能被其它窗口/线程的显示计数抵消；现在循环把计数推到隐藏侧，并在隐藏时持续 `SetCursor(NULL)`。
   - 开启 FPS/开放世界模式即消隐，不再依赖锚点；退出、按住才退出、Ctrl+Alt 交还或关映射时恢复箭头光标。

2. 开放世界模式
   - `Aim` 新增 `open_world`、`open_world_radius`、`open_world_smoothing`。
   - 鼠标相对位移映射到水平“触摸拖动带”；越过回中半径时抬指回到锚点并保留超出量，实现无限左右转向。
   - 不需要射击/开镜门控键，灵敏度、反转 Y、指针消隐仍沿用视角设置。

3. 组合键（可选）
   - 按键映射区增加“启用组合键”开关；关闭时组合键列表变灰失效。
   - 采用前缀键判定：第一个键是前缀，例如 `Ctrl+R` 先按 Ctrl、再按 R；有单键动作时 45ms 判定窗口，无单键动作时 120ms。
   - 引擎增加 `ComboGate`，组合完成时吞掉组件单键，避免 Ctrl 先触发 FPS 开关；组合动作支持点按/长按/滑动/系统键。
   - 组合键触点使用独立 lane/PID，并纳入设备 10 触点预算。

## 系统级指针消隐与 UHID 视角方案（2026-09-30 05:17:30 +08:00）

用户复测指出：本程序获得焦点时指针能消失，但焦点切到 scrcpy 后指针又出现。

最终修复：

- `ShowCursor/SetCursor` 都只对本线程/本窗口可靠，不能解决“焦点切到 scrcpy 窗口后指针重新出现”。
- Windows 改为用 `CreateCursor` 创建透明光标，并对 `OCR_*` 常用系统光标调用 `SetSystemCursor`，变成全局透明光标；退出捕获时用 `SystemParametersInfo(SPI_SETCURSORS)` 恢复系统方案。
- 程序启动时主动恢复一次系统光标，修复上次异常退出可能残留的透明光标。
- 主程序和鸿蒙 PC 捕获层都同步使用该系统级方案。

视角移动方案大改：

- 新增 `ViewInputMode`：`touch_drag`、`uhid_mouse`、`aoa_mouse`。
- `uhid_mouse`/`aoa_mouse` 使用 scrcpy 官方成熟路径：启动 scrcpy 时自动追加 `--mouse=uhid` / `--mouse=aoa`。
- 这两种模式不再把相对鼠标合成触摸拖动，因此不会经过键位/轮盘/游戏手势区域，也不会触发缩放等触摸副作用。
- `touch_drag` 保留作为兼容模式；开放世界模式的触摸拖动带继续可用。
- 视角设置可在映射开启前提前配置；只有真正进入视角模式的切换键在总映射开启后才生效。

后续调整（同一轮）：

- `--mouse=uhid` 改为点击[启动 scrcpy]时明确写入可见参数框，并同时补 `--keyboard=disabled`，避免 scrcpy 与本程序同时注入键盘。
- `--mouse=aoa` 取消自动添加，文档注明它与 ADB/USB 调试通常不能同时占用 USB，只适合 OTG 流程。
- 文档补充 UHID 被 scrcpy 捕获时按默认 Alt 交还，以及触摸拖动的游戏手势副作用警告。
