### 设计目的：已有的scrcpy二次创作的相关程序不好用，功能也比较单薄。基于我生活中对各种模拟器程序的使用经历，我决定自己制造一个好用的模拟器类似程序。

## 注意，使用scrcpy需要使用打开usb调试，使用本程序时手机必须用数据线连接电脑。打开usb调试的具体方法如下：
请在设置中搜索“usb调试”。点进相关界面。如果你是小米的系统，找到“usb调试”功能和“usb调试（安全设置）”功能，启用他（会有安全风险提示）。如果是其他品牌的手机同理打开相应的选项，不会的去网上搜教程，教的很详细。  
**注意，USB调试属于有风险的功能。请务必确保手机连接的设备是可信的。如果手机有需要频繁接入不同的电脑，请在使用后及时关闭usb调试功能。**  

## 安装注意

有关scrcpy，本仓库附带提供在windows或linux下可用的版本的压缩包，如果不想花时间找别处下载或对新版本不作要求，只需要下载本仓库里提供的压缩包，并将他解压到主程序（即scrcpy-pad-windows.exe，或scrcpy-pad-linux)同目录下即可。  
注意，所谓“同目录下”，指的是scrcpy-pad程序，和以scrcpy-xxxx为名的文件夹放在同一目录下。  
如果scrcpy找不到scrcpy，你也可以手动选择，在程序中选择“寻找scrcpy”等按钮，按照提示从相应目录选择即可。直到scrcpy，scrcpy-server和adb都被寻找到即可。  
本站scrcpy下载包就在仓库内，名为：  
windows版本：scrcpy-win64-v3.3.3.zip  
linux版本：scrcpy-linux-x86_64-v3.3.3.tar.gz  
作者不保证频繁更新之。  

如果你是windows用户，你只需要下载本仓库中的scrcpy-pad-windows.exe，和scrcpy（windows版本），解压scrcpy到程序同目录下后双击运行即可。  
如果你是linux用户，你需要下载本仓库的scrcpy-pad-linux（没有.exe)和scrcpy（linux版本），之后运行以下命令修改权限：
``` 
sudo usemod -aG input $USER
```
运行后输入管理员密码，注销重新登录即可。  

之后就可以成功运行了。

# scrcpy-pad

当前版本：**0.1.5**

> HarmonyOS 支持分为两条独立产品线：
>
> - [`harmonyos-pc/`](harmonyos-pc/README.md)：电脑端主产品线，通过 HDC、`uinput`、`uitest` 连接并控制 HarmonyOS 6+ 手机。
> - [`harmonyos/`](harmonyos/README.md)：可选手机端辅助应用，适合蓝牙/USB 键盘直连手机时使用，不参与电脑端主链路。
> - 独立辅助应用发布包：`release/harmonyos-companion/`。

基于 [scrcpy](https://github.com/Genymobile/scrcpy) 的键鼠映射工具，用于执行在电脑上把键盘按键映射为手机屏幕上的触控操作。

```
键盘/鼠标 ──► ┌─────────────┐      ┌──────────────┐      ┌──────────┐
              │  scrcpy-pad │ ───► │ scrcpy-server│ ───► │   手机    │
              │  (映射引擎)  │ TCP  │ (仅控制通道)  │ adb  │  游戏画面 │
              └─────────────┘      └──────────────┘      └──────────┘
                    画面由 scrcpy 本体窗口显示，与本程序互不干扰
```

## 1. 功能

### 1.1 动作类型

| 动作 | 说明 |
|---|---|
| 点按 | 按键触发一次触控点击。可设置触点持续时长；时长为 0 时表示按住不松手，直到再次按下同一键才抬起 |
| 长按 | 按住键盘期间手机触点保持按下，松开即抬起，实时跟随。与点按可一键互转 |
| 滑动（开发中） | 按键触发一次滑动。可分别设置起点、终点、时长、速率曲线与运动轨迹 |
| 系统键（开发中） | 注入 Android 系统按键（如返回 = 4、主页 = 3） |
| 宏（开发中） | 可录制按键时序，也可设置按键、组合键、轮盘、FPS、点击、滑动、间隔和嵌套宏；绑定触发键后按顺序执行 |

注意，滑动、系统键与宏处于开发阶段，实际应用效果可能与描述有出入。

### 1.2 轮盘（虚拟摇杆）

- 四个方向键（默认 WASD）驱动一个虚拟摇杆，支持八方向，松开自动回中。
- **半径**：拖"半径"数值框即可调整；也可点该行 **[改响应范围]** 后在截图上按住拖动（按下处到圆心的距离就是半径），或按 `Ctrl++` / `Ctrl+-` 缩放 —— 与按键的响应范围是同一套交互，点 **[完成]** 退出。
- **方向模式**：`经典(标准)` 保持旧行为，同轴左右（或上下）同时按住会互相抵消；`灵敏(后按覆盖)` 让同一轴最后按下的方向覆盖较早方向。后按方向先松开时，较早仍按住的方向会立即恢复。左右与上下分轴计算，因此斜向不会互相抵消。
- **影响范围**：方向键按下后手指实际被推多远 = 半径 × 系数。界面上那个圈仍然是"半径"，系数单独决定推出距离，因此可以把**看得见的圈**与**游戏里真实摇杆的判定圈**解耦：圈只是给眼睛看的参考，系数才是手感。取值范围 0.2 ~ 4.0，默认 1.0（推出距离等于半径，与旧配置完全一致）。不等于 1.0 时，截图浮层会额外画一圈**橙色虚线**表示实际推出距离，并在旁边标注像素值与倍数。点"影响范围复位"可一键回到 1.0。
- 临时轮盘：为轮盘设置"启用键"后，该轮盘仅在启用期间生效；启用期间其方向键的其它绑定自动让位，其余键位不受影响。支持"按住启用"与"再按切换"两种模式。
- **归属切换即时生效**：松开临时轮盘的启用键那一瞬间，仍被按住的键立刻恢复成它原本的功能（长按/系统键当场补上触点），**不需要松开手再按一次**；反过来，按下启用键的瞬间，已经按着的方向键也会立刻推动摇杆，而不是要重按。引擎始终维护一份"物理按键镜像"，凡是会让某个物理键改换门庭的操作（启用/停用临时轮盘、开关映射、在开打中增删键位）都会按它重新对账一遍。
- **轮盘类型**：`标准四向` 保持原行为；`自定义方向` 支持 2～8 个任意角度方向，每个方向一个按键，同时只接受最早按下的两个方向并取平均；`执行轮盘（开发中）` 按下方向键后从圆心快速滑到目标位置，用一次完整 swipe 代替“点中心再滑”的两步操作。
- **类型切换不丢数据**：标准四向的 W/A/S/D 与自定义方向表同时保留；在标准、自定义、执行之间切换时不会清空另一套方向数据。
- **中心有效区域/执行时长**：执行轮盘可调中心范围圆与滑动时长；半径、影响范围和截图拖拽改范围继续共用原交互。- 新建轮盘：点"新增轮盘"新建的摇杆半径固定 **150 像素**（按当前触摸坐标空间换算，界面上显示的就是这个值），并自动落在不与已有摇杆重叠的候选位置上 —— 不再出现"新建一个、旧的看起来突然变大/互相换位"的观感。截图浮层上摇杆编号与列表里的"轮盘N"一一对应。

### 1.3 滑动曲线与轨迹（开发中）

注意，本功能处于开发阶段，实际应用效果可能与描述有出入。

速率曲线（决定滑动过程中沿路径的进度分配）：

| 曲线 | 参数 | 说明 |
|---|---|---|
| 默认（匀速） | 无 | 进度随时间线性变化 |
| 加速曲线 | 幂次（默认 2） | 慢起快止 |
| 减速曲线 | 幂次（默认 2） | 快起慢止 |
| 钟形曲线 | 幂次（默认 3） | 起止慢、中间快 |
| 贝塞尔曲线 | x1, y1, x2, y2（默认 0.42, 0, 0.58, 1） | 即 CSS ease-in-out |

选择曲线后可点"设置..."调整参数，窗口内会同步绘制该速率函数的曲线图。

运动轨迹（决定路径的空间形状）：

| 轨迹 | 说明 |
|---|---|
| 默认（条形） | 起点到终点的直线 |
| 方形 | 起点为左上角、终点为右下角，沿矩形边界顺时针一圈 |
| 圆形 | 默认起点与终点为直径两端；可切换为"视为圆心"（起点为圆心、终点确定半径），并可另设"出发点"角度 |

### 1.4 响应范围

每个点按/长按键位有一个圆形响应范围（默认半径 35.2 像素）。点"修改响应范围"后该圆圈变黄，用 `Ctrl++` / `Ctrl+-` 缩放，或直接在截图上按住/拖动（按下时的位置到圆心的距离即半径）；点"完成"退出，当前的像素半径会显示在提示行里。缩放按固定比例逐步进行，除浮点精度外不设上下限；放大回到默认值附近时自动精确复位为默认半径。

修改范围期间，`Ctrl++` / `Ctrl+-` 会临时从"缩放整个界面"切换为"缩放该圆圈"（避免两者冲突：以前按下去界面变大、圆圈却没反应），退出修改后恢复界面缩放。

### 1.5 键位浮层

所有键位与轮盘叠加显示在手机截图上：绿圈 = 点按，橙圈 = 长按，黄圈 = 修改响应范围中/新增草稿，蓝线 = 滑动轨迹（内部半透明填充），青圈 = 永久摇杆，品红虚线圈 = 临时摇杆。可按 全部/仅键位/仅摇杆/永久/临时 过滤显示。摇杆浮层同时显示编号（与列表里的"轮盘N"对应）、方向键、启用键与模式。

**键位看得清吗**（左栏 [外观]）：默认开启 **键位自动对比** —— 截图上每个键位/摇杆底下的画面明暗会被采样，自动决定那一处用深色还是浅色；每个圈再描一圈**反相外套**、每个标注垫一层**半透明衬底**。这三招是"叠加在任意画面上的标注"的成熟做法：给线条加光晕（halo / casing）来自制图学，给文字垫底色（scrim）来自字幕行业（Netflix 的 Timed Text Style Guide 要求字幕必须带描边/阴影或底色块），自动对比则是本程序多出来的条件 —— 画布底下就是手机截图，可以直接采样。人眼对**局部对比度**敏感、而不是对绝对亮度敏感，所以同一个档位解决不了"亮块上太浅、暗块上太深"，逐块采样才行。

**键位显示亮度**滑块是在自动结果上的**微调**（往左整体加深、往右整体变浅）；关掉自动对比后它就等同旧版的固定档位（0 = 与旧版逐字节一致）。两者都只改明暗、不改色相：点按绿 / 长按橙 / 永久摇杆青 / 临时摇杆品红在任意档位下依然分得清，摇杆的"圆环 + 圆心小圈 + 方向标注"结构也原样保留。

**摇杆标注**：画布上的摇杆只标「摇杆N / 临时摇杆N」。想看方向键就**点一下那个摇杆的圈**，旁边弹出信息卡（上/下/左/右四个键名，临时摇杆另加启用键与模式），再点一下或点空白处收起。这样那串字不再长期压在游戏画面上挡视野。

> 浮层绘制使用的坐标空间优先取**截图尺寸**，因此同一张截图的浮层不会因为连接控制通道、手机转屏、后台刷新坐标空间而突然缩放或移位；若截图方向与当前触摸坐标空间不一致，画布上方会给出明确提示（此时建议重新截图后再取点）。

### 1.6 其它

- **总开关键**（默认 F8）：随时开关映射。关闭时自动释放所有触点与系统键，不会卡键；重新开启时会按当前**物理按键状态**对账一遍，此刻仍按着的键立刻生效。它是"按一下翻一次"——按键自动重复（按住不放时系统连发的重复按键）会被识别并忽略，不会把开关连翻好几次。
- **映射状态可见**：顶栏的 `映射: 开/关` 按钮带颜色，**每一次开关都会写进日志**（是总开关键按的还是顶栏按钮点的）。遇到"按键不反应"时先看日志：十有八九是映射被误关了 —— 以前这一步完全没有记录，只能靠反复按 F8 试。
- **切走再回来也认得**：空闲 3 秒以上又收到按键时，程序会顺手重新确认一次触摸坐标空间（切到别的窗口待一会儿的功夫，手机可能已经转过屏）。以前坐标空间只在开映射/截图/连接时更新，过期后会表现为"按键不反应"，而"关一次开一次映射"恰好会刷新它 —— 现在不必手动关开了。
- 引擎状态自检：左栏显示"引擎: 触点 n/10 · 因触点池满被放弃 N 次"。设备端同时最多认 10 个触点（普通键位 + 摇杆 + 瞄准共用这一个池子），超出的按下会被设备直接丢弃（表现为"按了没反应、原因不明"）。程序现在自己守住这个上限，并把"哪一次按下因为挤不进去被放弃、是哪个键"记下来显示在这里（日志里也会写一条）；结构变化（增删键位/摇杆）时也会先把在按的触点全部抬起再重建状态，不会把触点漏在手机上越攒越多。
- 截图取点：截取手机屏幕后，点击图像完成坐标设置。新增点按/长按时，取点后若尚未指定按键，会立即进入按键捕获状态；点 **添加** 之后该次操作即结束，不会再停留在取点状态。
- 交互态互斥：取点 / 改键 / 修改响应范围 同一时刻只有一个，以最后一次操作为准。
- 坐标不设边界：键位允许落在画面之外，程序不会做越界"纠正"；旧版像素坐标只在**尺寸确实装得下**时才会自动换算成相对坐标（竖屏截图的尺寸绝不会拿去换算横屏布局，避免把键位算坏）。
- scrcpy 管理：可以直接指定 scrcpy 所在**目录**（最省事，填一个就够），也可以只填 scrcpy.exe / scrcpy-server / adb.exe 其中一个，其余留空会自动从同目录补齐；另可自动寻找或手动指定，并测试可用性。
- **记住路径**：勾选"记住路径"后，scrcpy 目录与三个路径、启动参数、上次使用的设备都会写入配置目录的 `settings.json`（与 `profile.yaml`、`look.json` 同目录），下次启动**直接沿用**，即使 scrcpy 目录不在程序同级、或装在任意位置，也不必重新寻找。几点说明：
  - 记住的是**目录**时同样有效：程序会在该目录（含"再套一层文件夹"的情况）里找 `scrcpy.exe`，并顺带补齐 server 与 adb；文件对话框里选中的是文件夹也按目录处理。
  - 路径被搬走/升级换版本也不会丢：程序会记住"它原来在哪个目录"，下次启动在那附近重新找回（只往名字像 `scrcpy` 的子目录里下探，因此即便线索落在桌面/下载这类大目录也不会拖慢启动）。
  - 关掉"记住路径"只是"下次启动不再使用"，**不会**清空文件里已记住的路径；开关状态本身会立刻落盘，不会出现"关掉了、下次启动又自己打开并把旧路径读回来"。
  - 配置文件被编辑器加上 UTF-8 BOM（Windows 记事本常见）也能正常读取；真的解析不出来时会另存一份 `xxx.json.broken` 并打印原因，不会静默覆盖掉用户的配置。
  - 点"打开配置目录"可在文件管理器中查看这三个文件。路径与键位配置**分开存放**是刻意的：键位配置是可传递、可另存的用户资产，而"这台电脑上 scrcpy 装在哪"是本机私有的环境信息，混在一起会导致把配置发给别人时带上自己的绝对路径。
  - 启动 scrcpy 时，程序会记录完整命令、自动追加参数、stdout、stderr 和退出码到 `diagnostics.log`，并把关键输出同步到左侧日志区；参数报错不再只显示“已启动”。
- scrcpy 参数助手：参数框旁 `...` 打开常用参数列表，含中文说明、使用示例、双击临时编辑与一键加入。
- 启动预设：启动按钮旁下拉可选 无 / 2k / 4k / 1k / 720p / 不使用音频输出 / 使用音频输出。分辨率预设会先重置为初始参数再叠加 `--max-size`；音频预设直接在现有参数上增删 `--no-audio`。注意 `--max-size` 是**上限**：scrcpy 只缩小、不放大，设备本身能输出多高，画面上限就是多高（选了 4k 而设备只有 1080p 时，实际仍是 1080p，此时日志会给出提示）。
- 配置管理：保存、另存为、选用已有 yaml、在指定路径新建、切回默认配置、校验当前 yaml 合法性。
- **按键组合与切换键位**：一份 `profile.yaml` 可包含多套相互独立的按键组合（键位/轮盘/瞄准/外观），并可为任意切换键指定目标组合；切换时先抬起旧组合的所有触点，再按当前物理按键状态重建，开打中换车也不会卡键。
- 外观设置：配色 / 控件密度 / 背景图 / 键位显示亮度等改动既随配置保存，也会自动缓存到程序目录（与键位配置同目录的 `look.json`），重启后仍保持上次外观，不必每次重调。该文件由程序自动读写，暂不提供手动编辑或单独选择。
- 撤销/重做：顶栏按钮或 Ctrl+Z / Ctrl+Y。
- 保存日志：导出设备型号、Android 版本、分辨率、主机环境与运行日志。
- 多点触控：轮盘与按键各有独立触点，可同时进行；普通按键之间互不干扰，最多 8 键同时按下（与摇杆、瞄准共用一个 10 触点的设备池）。
- 摇杆信息卡：在画布上点某个摇杆的圈即弹出它的四个方向键（临时摇杆另加启用键与模式），再点收起；画布上只留「摇杆N」。

### 1.7 鼠标视角（FPS / 开放世界）（开发中）

- **拖动死区**：鼠标累计位移在死区内不注入 `touch_move`，用于过滤手抖；越过死区后才开始移动手指。
- **有边界/无边界**：有边界时触点按屏幕边缘截断，到边即停；无边界时到达“回转半径”会无缝抬指、在锚点重按并保留超出量，配合指针消隐可持续左右转向。`静止归中` 到达设定毫秒数后自动抬指回锚点。
- **瞄准锚点单独成栏**：默认不自动设置锚点。锚点不是游戏准星，而是虚拟手指落下的起点，应取在游戏 UI 之外的干净区域；未设置时 FPS 触摸拖动会保持待机并给出提示。

注意，本功能处于开发阶段，实际应用效果可能与描述有出入。

- 视角设置（含开放世界模式、开关键、视角输入方式）在映射开始前就可以提前配置；真正按开关键进入模式时才会检查总映射是否已开启，避免开打前抢 Ctrl 等快捷键。
- **[视角输入]**：`触摸拖动（通用，默认）`、`虚拟手柄右摇杆（连续）`、`虚拟手柄右摇杆（分段回中）` 三选一。旧版的 `UHID 相对鼠标` / `AOA 相对鼠标` 已移除；旧配置会自动迁移回触摸拖动，避免 scrcpy 自动捕获鼠标。虚拟手柄模式由本程序通过 scrcpy 控制通道创建 Xbox 360 兼容 HID 手柄，把鼠标位移喂给右摇杆，不产生触摸轨迹；游戏需要支持手柄右摇杆控制视角。连续模式适合顺滑追视角；分段回中模式在摇杆到达极限后保持极限一小段时间，再归中并保留超出量，模仿人类一段一段滑动视角。面板自检会显示“虚拟手柄已创建”和已发送的输入报告数。
- 只有虚拟手柄模式会在点击 **[启动 scrcpy]** 时自动追加 `--mouse=disabled --keyboard=disabled --gamepad=disabled`；追加后的完整参数会立即写进上方参数框并记入 `diagnostics.log`。普通触摸拖动模式不再自动修改 scrcpy 的鼠标参数，因此不会因为旧设置而自动进入鼠标捕获。
- **[开放世界模式]**：在触摸拖动输入下不需要射击/开镜键。鼠标相对位移会映射到一条“触摸拖动带”，水平方向越过回中半径时保留超出量无缝换手，因此可以无限向左/向右转向；水平回中半径和平滑系数可调。若游戏支持手柄右摇杆，可改为虚拟手柄连续模式，通常比触摸轨迹副作用更小。
- **[按住才退出]**：在 FPS 模式中按住该键会暂时退出 FPS、恢复普通键位映射并显示系统光标；松开后自动回到 FPS。
- **[指针消隐]**：默认开启。触摸拖动和虚拟手柄模式下，Windows 会用透明系统光标（`SetSystemCursor`）替换系统光标，因此即使焦点在 scrcpy 窗口也会消失；退出捕获时通过系统光标方案恢复，程序启动时也会修复上次异常退出留下的透明光标。
- 普通键位列新增 **[仅 FPS]**：勾选后该键只会在 FPS 模式生效并显示，且同键会覆盖普通映射；支持点按、长按、滑动、系统键，以及鼠标左/右/中键、侧键和滚轮。滚轮统一映射为 `BTN_WHEEL_UP/DOWN/LEFT/RIGHT`（277~280）。
- 灵敏度、**视角移速**、反转 Y、归中（静止 / 阈值 / 不归中）可调；移速作用于触摸拖动、开放世界和虚拟手柄右摇杆，1.0 为原速。可绑 **[按住才瞄准]**（如鼠标右键开镜）。
- FPS 模式内仍可按 `Ctrl+Alt` 临时把鼠标交还系统，再按一次收回。

#### 组合键（可选）

- 在 **按键映射** 区勾选 **[启用组合键]** 后，组合键列表才生效；关闭时组合键设置保留但整体变灰失效。
- 组合键采用“前缀键”判定：第一个键作为前缀，后续键要在前缀仍按住时按下，例如 `Ctrl+R` 先按 Ctrl 再按 R。
- 前缀键有单键/功能键映射时使用 45ms 快速判定窗口；没有单键映射时使用 120ms 窗口，以降低快速组合的误触。组合完成时前缀键和成员的普通单键动作会被吞掉，不会先触发 FPS 开关或其它单键。

### 1.9 关键注意事项（2026-10-01）

- **指针消隐是系统级修改。** 触摸拖动视角模式使用透明系统光标（`SetSystemCursor`），焦点切到 scrcpy 窗口也会隐藏；正常退出会恢复。若程序被强制结束，透明光标可能暂时残留，重新启动本程序会自动恢复系统光标方案。
- **UHID/AOA 已从界面和自动启动逻辑中移除。** 旧版本可能把 `--mouse=uhid` 或 `--mouse=aoa` 保存进 `settings.json`；本版启动时会主动清除这些旧参数，并进行日志提示。若你必须手动实验相对鼠标，请自行在参数框加入 scrcpy 参数并确认鼠标捕获风险。
- **触摸拖动仍有兼容性代价。** 它本质上是在手机屏幕上制造手指轨迹，轨迹经过游戏按钮、轮盘或手势区域时可能产生副作用。请把锚点放在游戏没有 UI、不会触发缩放的干净区域；需要更适合视角转向时优先测试虚拟手柄右摇杆。
- **组合键采用前缀判定。** 第一个键是前缀，例如 `Ctrl+R` 必须先按 Ctrl 再按 R。前缀有单键动作时为 45ms，快速按下第二个键才判为组合；没有单键动作时为 120ms。若按下间隔超过窗口，会先执行前缀单键动作。
- **视角模式设置可以提前做，但进入模式必须等总映射开启。** 这是为了避免开打前 Ctrl/Alt 等快捷键被程序抢走。开关键本身可以在映射前捕获，真正按下时如果总映射未开则不会进入视角模式。
- **虚拟手柄右摇杆是另一条“无触摸副作用”路线。** 它创建标准 Xbox 360 兼容 HID 手柄，只驱动右摇杆 X/Y 轴；游戏必须支持手柄右摇杆视角。连续模式停止移动后会自动回中；分段模式到达摇杆极限会归中并保留超出量，适合模仿人类分段滑动视角。

**研究结论：** scrcpy 的 UHID 鼠标是标准相对 HID 鼠标，Android 通常会显示鼠标指针，而且会接管鼠标/键盘焦点；AOA 是 USB OTG 级 HID，正常情况下不能与 ADB 同时占用 USB。实际测试证明两者都不适合作为默认自动方案，因此本版已从界面移除自动启用。只认触摸的游戏仍需用触摸拖动兜底；虚拟手柄右摇杆适用于支持手柄视角的游戏，是目前较值得先测试的“无触摸轨迹”路线。要做到完全无副作用，需要游戏自身支持鼠标/手柄视角，或设备端获得系统签名/特权能力做专用注入。

### 1.11 界面风格（主题：默认 / 鸿蒙 / 可视化）

左栏 **[外观] → 界面风格** 提供三种整体风格。风格与"配色"是两个独立维度：深色/浅色/Nord/Catppuccin 四种配色在**默认 / 可视化**两种风格下都保留。

| 风格 | 说明 |
|---|---|
| 默认 | 原有界面布局（顶栏 + 左配置栏 + 中央四标签页），不使用主题功能的老用户观感不变 |
| 鸿蒙 | **照 `harmonyos-pc/`（scrcpy-pad HarmonyOS HDC）那套浅色 UI 重新设计的界面**：紫色标题栏 + 白底顶栏 + 左侧图标导航 + 中央卡片页 + 右侧屏幕预览 + 底部状态栏（详见下） |
| 可视化 | 虚拟键盘 + 虚拟鼠标取键的编辑界面（详见下） |

- **切换需要关一下再开**：风格牵动整体布局，无法像配色那样热应用。在选择器里换风格后，程序会**自动关闭窗口并立刻用新风格重新打开**（日志里有记录），确保完全切换完毕。
- **记住主题**：风格与其它外观设置一起写入配置目录的 `look.json`，**下次启动自动沿用上次选的主题**；此外**切换按键组合（含切换键）也不会把主题带走** —— 风格是界面级设置，由界面侧每帧盖回共享配置。
- 默认 / 可视化风格下，面板不透明度、背景图、四种配色等原有外观能力全部保留；**鸿蒙风格是一套完整的浅色界面**（页面底 `#F4F7FB`、白卡片、蓝主色 `#2384FF`），不再跟随深色配色。

**鸿蒙风格的布局（照 HDC UI 重排）**：

- **顶栏**（白底细线）：`● scrcpy-pad 触控映射` + 设备下拉 + 状态 pill（控制已连接 / 未连接、映射 开/关）+ 右侧主操作（使用说明 / 刷新设备 / 连接控制·断开 / 保存配置）。
- **左侧导航**（图标 + 文字，选中项淡蓝底蓝字）：**连接与设备 / 按键映射 / 宏 / 虚拟轮盘 / FPS 模式 / 外观 / 诊断**；底部放 撤销 / 重做 / 关于。
- **中央卡片页**：每页由白底圆角卡片组成（14px 圆角 + 细描边），内容与默认风格**共用同一份实现** —— 例如"按键映射"页的配置、键位列表、组合键与左栏里的是同一套控件，不存在"鸿蒙少了某个功能"。
- **右侧"屏幕预览"**：就是截图取点区（截取手机屏幕 / 缩放 / 重置 / 画布），固定在最右侧，可拖动宽度。
- **底部状态栏**：最新一条日志 + 引擎状态（触点 n/10）。

**可视化风格的操作方式**：

- **点键取键**：中央是一张**老式机械键盘外观**的标准美式全键盘（深色机身底盘 + 灰色键帽 + 鲜明描边 + 立体裙边，含导航区与小键盘），右侧是一只虚拟鼠标（左右键/中键/侧键/滚轮上下）。
  - 点**已设置的键**：选中它（高亮 + 白描边），键盘下方出现操作栏 —— 内容与右栏列表**同一套**编辑器，取点 / 改键 / 转长按 / 修改响应范围 / 删除 / 仅FPS / 撤销保存等全部保留。
  - 点**空闲键**：直接为它新建键位草稿并**立刻进入截图取点**（截图取点的位置与操作不变）；取点中该键在键盘上呼吸闪烁。不想继续就点操作栏的 **[取消取点]**。
  - 也可以先点操作栏的 **[取点]** 再按老流程设置，两种顺序都行。
- **空键位不再"隐形"**：未设置的键是半透明灰键帽 + 一圈鲜明描边（旧版 alpha 14 几乎看不见），深色/浅色界面下都能看清整张键盘。
- **颜色语义**：键位=绿、仅FPS=橙、摇杆方向=青/品红（永久/临时）、组合键与切换键=蓝、FPS 瞄准三键与总开关键=红。
- **两个页面的显示能力完全一样**：键位页与 FPS 页各有一组 **显示按键映射 / 显示宏 / 显示组合键映射 / 显示摇杆 / 显示FPS** 勾选，勾上就能看到对应的键亮起；区别只是**默认值** —— FPS 页默认只显示"仅 FPS"键位（普通映射/宏/组合键/摇杆需要手动勾上）。FPS 页仍然**只能编辑 FPS 相关键**：点"仅 FPS"键位、FPS 宏或瞄准三键可直接编辑，点到被普通映射/摇杆占用的键会给出提示。
- **标签页布局**（可视化风格下）：右侧三张 **键位**（含组合键与摇杆列表）/ **FPS 设置** / **其他功能**；左栏中部三张 **键位组合** / **外观** / **诊断**（默认选中"键位组合"）。
- 操作栏按钮是"浏览器标签页"式（方形、不立体、大小不变）；日志仍在左栏下方，截图取点仍在右下方固定区。

## 4. 使用步骤

1. 手机开启 USB 调试并连接电脑。
2. 启动 scrcpy-pad。程序会自动寻找 scrcpy 并检测版本，左栏显示结果。找不到时在左栏 **scrcpy 管理** 里直接填/选 scrcpy 所在**目录**（填一个就够，其余自动补齐），并勾选 **记住路径**，之后每次启动都直接沿用。
3. 顶栏下拉选择设备，点 **连接控制**（建立注入通道，成功后显示绿点）。
4. 点 **启动 scrcpy**，弹出手机画面窗口。
5. 点 **截取手机屏幕**，游戏画面进入程序。之后配置键位与轮盘。
6. 按 **F8** 开启映射；再按 **F8** 关闭。

### 4.1 配置轮盘

1. 四个方向按钮逐个点选后按物理键（默认 WASD）。
2. 点 **取圆心**，在截图上点击游戏摇杆中心。
3. 调半径：拖"半径"数值框，或点该行的 **改响应范围** 后在截图上按住拖动（按下处到圆心的距离就是半径），也可用 `Ctrl++` / `Ctrl+-`（新建轮盘的初始半径是 150 像素；多个轮盘会自动错开摆放，互不重叠）。
4. 如需临时摇杆，点该行的 **启用键** 捕获一个键，并选择"长按启用"或"再按切换"。
5. 临时摇杆启用期间，其方向键归摇杆、同键位的其它绑定让位；**松开启用键的瞬间**，仍按在手上的键立刻恢复原功能，不必松手重按。

### 4.2 配置按键

1. 在"新增"行选择类型（点按 / 长按 / 滑动（开发中） / 系统键（开发中））。
2. 点"未绑定"按钮，按下要绑定的物理键。
3. 按类型设置参数：
   - 点按/长按：x、y、响应范围；点按另有触点时长（0 表示按住切换）。
   - 滑动：分别点 **取起点** 与 **取终点** 在截图上取点，设置时长、曲线、轨迹；曲线参数点 **设置...** 调整。
4. 点 **添加** 加入列表。若还想要精确落点，在点"添加"之前先点 **取点** 在截图上点一下即可；**添加完成后这次操作就结束了**，不会停留在取点状态（界面上也不会再显示"取点中"）。要改坐标就点该行的 **取点**。
5. 已添加的键位可在行内直接修改参数：改写按键、调整数值、**取点**（仅改坐标）、**转长按/转点按**、**修改响应范围**、**删除**。
6. 取点、改键（捕获按键）、修改响应范围这三种"交互态"互斥，**以最后一次操作为准**：正在修改响应范围时点 **取点**，会直接退出修改并转去取点，不会两头挂着。

### 4.3 保存与分享配置

- 默认配置文件：`~/.config/scrcpy-pad/profile.yaml`（Windows 为对应的用户配置目录）。
- **保存配置**：写入当前指向的配置文件。
- **另存为...**：导出为独立 yaml。
- **选用配置...**：选择任意 yaml 作为当前键位，加载前会校验合法性。
- **新建配置...**：在指定路径创建一份默认配置并切换过去。
- **默认配置**：一键切回程序默认的配置文件（即本节开头那个默认路径，首次运行时由程序自动创建）并加载它的内容；该文件若已被删除，会按出厂默认重新写一份。当前配置区下方那行"当前配置文件"会标出是否正指向它（显示" (默认)"）。
- **检测当前 yaml**：校验当前配置文件是否符合格式要求。

|---|---|
| `Ctrl+Z` / `Ctrl+Y` | 撤销 / 重做 |

## 5. 工作原理

- 启动一个 control-only 的 scrcpy-server（`video=false audio=false control=true`，独立 scid），仅作为触控注入通道，与 scrcpy 画面窗口互不干扰。
- 直接实现 scrcpy 控制协议（触控消息 32 字节大端序列化），事件驱动，与官方客户端延迟同级。
- 全局键盘捕获：Linux 用 evdev（`/dev/input`），Windows 用自建 WH_KEYBOARD_LL / WH_MOUSE_LL 低级钩子。
- 键码统一为 Linux evdev 码空间，配置文件在两平台通用。
- 文件对话框：Linux 用 xdg-desktop-portal，Windows 用 Win32 原生。

## 7. 常见问题

**提示"输入捕获不可用 / 无权限"**
执行 `sudo usermod -aG input $USER` 后未重新登录。注销重登，或用 `sg input -c './启动.sh'` 临时借组运行。

**连接控制失败**
确认 `adb devices` 能看到设备，且 scrcpy-server 路径存在。找不到时在左栏手动指定（填 scrcpy 所在**目录**最省事；Linux/Windows 的斜杠方向均可）。

**Windows 上 scrcpy 画面正常，但顶栏一直"无设备"**
列设备使用程序自己的 adb；官方 Windows 发行包的 adb.exe 与 scrcpy.exe 同目录且不在 PATH 中。在左栏 **scrcpy 管理** 中填/选 scrcpy 所在**目录**（或浏览选择 scrcpy.exe / scrcpy-server / adb.exe 任一），其余会自动补齐并刷新设备。

**开了映射但按键没反应**
按顺序看三处：① 顶栏的 `映射: 开/关` 是不是"关"（日志里有每次开关的记录，能看到它是什么时候、被谁关掉的 —— 总开关键按住不放时系统连发的重复按键以前会把开关连翻好几次，现在不会了）；② 左栏 **引擎状态** 一行里"因触点池满被放弃 N 次"若不为 0，说明那一刻同时按住的键 + 摇杆 + 瞄准超过了设备端 10 个触点的上限，那一次按下会被设备直接丢弃，少按几个键即可，括号里会写明是哪个键；③ 如果你刚在别的窗口待了一会儿，程序会在你下次按键时自动重新确认一次触摸坐标空间（手机可能转过屏），稍等一次按键即可。

**画的圈看不清（背景太亮/太花）**
[外观] 里的 **键位自动对比** 默认是开的：它按截图逐块采样，自动决定每一处用深色还是浅色，并给圈描反相外套、给标注垫半透明衬底。若还想微调，用同一处的 **键位显示亮度** 滑块（往左整体加深、往右整体变浅）；完全不想要自动行为就关掉自动对比。

**画布上摇杆只写"摇杆2"，方向键在哪看**
点一下那个摇杆的圈：旁边会弹出信息卡列出上/下/左/右对应的键（临时摇杆还会显示启用键与模式），再点一下或点空白处收起。

**新建轮盘后，旧轮盘看起来变大 / 两个摇杆像换了位置**
已修。旧版新建轮盘固定用"屏宽的 1/9"作半径（在宽屏手机上比手调的大一圈），落点也固定写死；同时浮层用的坐标空间会在连接/转屏时变化，导致整层浮圈突然缩放。现在新建轮盘半径固定 150 像素、落点自动避开已有轮盘、浮层按截图尺寸绘制并标注编号（与列表"轮盘N"对应）。

**设置好 scrcpy 目录后，重启还是找不到**
现在的做法：左栏 **scrcpy 管理** 里直接填/选 scrcpy 所在目录 → 点 **应用**（或直接勾选 **记住路径**），日志会立刻显示"设置已保存: …\settings.json"。若仍不生效，点 **打开配置目录** 检查 `settings.json` 里是否写有 `scrcpy_dir`/`scrcpy_path`：关掉[记住路径]时路径不会写入（日志里也会明确说明）；`settings.json` 解析失败时会打印原因并留下 `settings.json.broken` 副本。

**游戏时想打字**
按 F8 关闭映射即可。

**临时轮盘的方向键平时还能用吗**
能。未启用期间方向键的普通绑定照常生效；启用瞬间引擎会自动释放冲突触点，停用瞬间又会把仍按着的键补回来。

**按住一个键再连点另一个键时，另一个键不响应**
点按为抢占式触发，任意速度的连点都会完整触发；普通键位最多 8 键同时按下（与摇杆、瞄准共用一个 10 触点的设备池）。若在模拟器上仍无效，通常为该模拟器的多点触控能力限制，可用真机对比确认。

### 2026-09-21（第二轮）

- **浮层可读性重做（"看不清键位"）**：上一轮只给了"调亮度"的滑块，但画面上既有亮块又有暗块，同一个档位解决不了 —— 这次按成熟做法三招齐上：
  - **描边/外套**：所有响应圈（键位、摇杆、滑动轨迹、锚点、影响范围外环）都先画一圈**反相**的粗线再画本色线。给线条加光晕（halo / casing）是制图学的常规手法，用于让线条在任意底图上都可见（ICC 2013《Guidelines for Consistently Readable Topographic Vectors and Labels with Toggling Backgrounds》）。
  - **衬底**：所有标注文字下面垫一块**反相**的半透明圆角色块（scrim）。字幕行业的标准做法就是"描边/阴影，或者半透明底色块"（Netflix Timed Text Style Guide）。
  - **自动对比**（默认开启，可在 [外观] 关掉）：截图被缩成至多 64×64 的亮度网格，每个键位/摇杆按**自己底下**的画面明暗自动决定用深色还是浅色。人眼对局部对比度敏感、而不是对绝对亮度敏感，所以逐块采样才是正解 —— 这是本程序比一般 HUD 多出来的条件：画布底下就是手机截图。
  - 手动滑块降级为"微调"（在自动结果上叠加偏移）；关掉自动对比后等同旧版的固定档位，0 档仍与旧版逐字节一致。
- **摇杆标注瘦身 + 点一下看方向键**：画布上的摇杆只标「摇杆N / 临时摇杆N」，原来那串 `临时摇杆2[KeyE·按住] KeyI/KeyJ/KeyK/KeyU` 不再长期压在游戏画面上；想看方向键就在截图上**点一下那个摇杆的圈**，旁边弹出信息卡（上/下/左/右 + 临时摇杆的启用键与模式），再点一下或点空白处收起。选中的摇杆会多描一圈细环。
- **"按下 F8 没反应 / 必须关一次开一次才恢复"**：根因是 Windows 的按键自动重复会被全局钩子报成一串 KeyPress，而旧代码对**每个事件**都翻转一次映射开关 —— 按住 F8 半秒就能翻十几次，状态于是和用户以为的相反，而且当时**没有任何日志**可查。现在总开关键与"再按切换"的临时轮盘启用键都只认**按下的那一瞬间**（上升沿）。
- **映射状态可见**：引擎新增一条"给界面日志留一句话"的通道 —— 每一次映射开关（按的是总开关键还是顶栏按钮）、每一次"因触点池满导致某次按下被放弃（含是哪个键，每秒最多一条）"、以及"配置变化时先把在按的触点抬起来再重建"都会写进日志。
- **切走再回来也认得（坐标空间自检）**：以前触摸坐标空间只在开映射/截图/连接时更新，切到别的窗口待一会儿（手机可能已转屏）再回来，注入会落到错误的位置，表现同样是"按键不反应"，而"关一次开一次映射"恰好会刷新它 —— 现在空闲 3 秒以上又收到按键时会自动重新确认一次。

### 2026-09-21

本轮是四件事的修复：**普通按键按下没反应**、**临时摇杆松开启用键后按键要松手重按**、**新建摇杆的半径与落点**、**记住的 scrcpy 路径重启后失效**。

- **触点不再漏抬（"普通按键按下无反应"的根因）**：设备端 scrcpy-server 同时只认 10 个触点，多出来的按下会被**直接丢弃**（不是排队），在玩家侧就是"按了没反应、原因不明"。而旧引擎有三处会漏掉触点：① 增删键位时按下表按索引跟踪，索引整体位移后旧触点永远留在设备上、并把"已按下"错记到别的键；② 增删摇杆时直接 `vec![默认值]` 重建状态，正在推的摇杆触点就此卡在手机上；③ 没有上限意识，普通键位 + 摇杆 + 瞄准一起抢那 10 个名额，超出的按下白发给设备。现在：绑定表/轮盘表各有"结构指纹"，指纹一变就先**把在按的触点全部抬起**再按新配置重建（只改坐标/半径不触发，避免边打边调参被反复抬手）；注入前的触点预算统一按设备上限 10 计算，挤不进去的按下降级为"明确拒绝 + 记一次诊断"而不是发出去被丢掉；左栏新增引擎状态自检，直接显示"触点 n/10 · 因触点池满被放弃 N 次（最近是哪个键）"。
- **临时摇杆的归属切换即时生效**：以前"按住 K 连招 → 按一下启用键 → 松开启用键"之后，K 仍按在手上却失效了，必须松手重按一次才恢复。原因是键盘事件是边沿触发的，K 的普通绑定在启用瞬间被释放后，再也收不到那一次"按下"。现在引擎维护一份**物理按键镜像**（所有按键事件先落到它），启用/停用临时轮盘、开关映射、开打中增删键位之后都按它重新对账一遍：松开启用键的瞬间，仍按着的长按/系统键立刻补上触点；按下启用键的瞬间，已按着的方向键也立刻推动摇杆。
- **新建摇杆**：半径不再写死成"屏宽的 1/9"（那在 2772 宽的横屏手机上就是 307px，比用户手调的大一圈），改为固定 **150 像素**（按当前坐标空间换算，界面上显示的就是这个值）；落点改为在不与已有摇杆重叠的候选位置里挑一个，并在浮层标注编号（与列表"轮盘N"对应），不再出现"新旧摇杆糊在一起、看起来换了位"。
- **画布几何稳定**：浮层绘制用的坐标空间改为**优先取截图尺寸**（以前优先取控制通道尺寸，而它会在连接、转屏、后台刷新时变化，于是同一个摇杆会毫无征兆地突然变大或移位）；画布缩放系数也只跟窗口高度与截图尺寸有关（以前用"当前剩余高度"，右侧多一行设置就会让整张浮层跟着缩放）。截图方向与当前触摸坐标空间不一致时会明确提示，并建议重新截图再取点。
- **键位显示亮度（新增）**：截图上键位/摇杆的响应范围圈与标注可整体加深或变浅（左栏 [外观] 里的滑块，0 = 默认）。只改明暗不改色相，语义色在任意档位都分得清；摇杆的圆环 + 圆心小圈 + 方向标注结构保持不变，看上去仍然是个摇杆。标注文字自带对比描边（亮字配暗描边、暗字配亮描边），因此加深到近黑字、变浅到纯白字都读得清；填充透明度跟着反向微调，且不会盖住截图内容。
- **scrcpy 路径记忆彻底修好**：
  - 可以直接指定 **scrcpy 目录**（新增"浏览目录"按钮与输入框，`settings.json` 里新增 `scrcpy_dir` 字段）：程序在该目录（含"再套一层文件夹"）里找出 `scrcpy.exe`，并顺带补齐 server 与 adb；文件对话框选中的是文件夹也按目录处理。
  - 记住的位置被搬走/升级换版本后不再一丢了之：清掉死路径时会**保留它的位置线索**（所在目录，必要时上溯一级），下次启动在那附近重新找回（只往名字像 `scrcpy` 的子目录里下探，因此线索落在大目录上也不会拖慢启动）。
  - **修掉一个会毁配置的 bug**：`saved_at`（落盘时间戳）以前参与"内容是否变化"的比较，于是"已落盘内容"与"下一帧登记的内容"永远不相等 —— 结果是**每 120ms 就写一次盘**；同时"关掉[记住路径]"这一动作因为提前 return 而永远写不出去，下次启动又变回"记住"并把旧路径读回来。现在比较只认用户真正改动的字段，开关状态也会立刻落盘，关掉时**不清空**文件里已记住的路径。
  - **BOM 容错**：配置文件若被编辑器（Windows 记事本）加上 UTF-8 BOM，以前会被当成损坏 → 退回默认值 → 下一次落盘把用户内容整份覆盖（这正是"settings.json 里根本没有 scrcpy 位置信息"的一种成因）。现在读取统一去掉 BOM；真的解析失败时会另存一份 `xxx.json.broken` 并打印原因，不再静默覆盖。
  - 选完路径/目录、点[应用]、[自动寻找全部]、勾选[记住路径]时都会立刻落盘并在日志里给出确认，不再出现"设置了却不知道有没有记住"。
  - 另外：`启动.bat` 优先运行 `release\windows-x86_64\scrcpy-pad.exe`，而该产物此前停留在没有路径记忆功能的旧构建上 —— 本轮已重新打包同步。

### 2026-09-19（续 · 开发版）

- **摇杆"影响范围"可调**：轮盘新增"影响范围"系数，触点实际推出的距离 = 半径 × 系数（0.2 ~ 4.0，默认 1.0）。半径仍然决定截图上那个圈的大小，系数单独决定手指推多远，于是可以把"看得见的圈"和"游戏里真实摇杆的判定圈"解耦；系数不为 1.0 时浮层多画一圈橙色虚线表示真实推出距离，旁边标注像素值与倍数，"影响范围复位"可一键回到 1.0。默认值取 1.0 是为了让老配置读进来后行为逐一致（`scope` 走 `#[serde(default)]`，缺字段即 1.0，并有单测锁死这一点）。
- **新增路径记忆**：勾选"记住路径"后，scrcpy / scrcpy-server / adb 路径、启动参数与上次使用的设备写入配置目录的 `settings.json`（与 `profile.yaml`、`look.json` 同目录），重启后直接沿用，不必重新寻找；记住的路径若已失效会自动丢弃并回落到自动寻找。左栏新增[记住路径]开关与[打开配置目录]按钮。配置写入延迟到帧末、内容未变则跳过，因此不会反复写盘。
- **修复卡键隐患**：顶栏"映射: 开/关"按钮以前只翻转开关状态，不执行收尾，于是"用按钮关映射"会把仍按着的长按触点永久留在手机上。现在关闭映射的收尾（抬起全部触点、松开系统键、停用临时轮盘、抬掉瞄准触点）抽成一份共用实现，顶栏按钮与总开关键走同一条路径：按钮只置一个请求位，由引擎线程在 4ms 内完成收尾。
- **修复 Windows 鼠标瞄准的一次假位移**：鼠标捕获期间把光标拉回屏幕中心后，那次由回中自身触发的鼠标事件没有被跳过，会被当成一次真实位移上报，表现为视角突然反向跳一下。现已一并跳过。
- **引擎开销**：未连接设备 / 未开启映射时，引擎轮询从每 4ms 一次退避到每 16ms 一次（这两种状态下循环体本就不做任何事），不再空转消耗 CPU；事件到达仍会立刻唤醒，响应延迟不受影响。到期的定时动作改为整批处理，一次加锁而不是每个动作加两次锁（滑动一次会排入几十个移动指令，收益明显）。鼠标位移与撤销快照也不再深拷贝整份配置。
- **协议层加固**：新增 3 个序列化单测，逐字节锁死 32 字节触控消息与 14 字节按键消息的字段布局（含压力值、`action_button`/`buttons` 恒为 0、大端序），负坐标夹到 0。
- **启动器**：找不到可执行文件时会先编译，并直接使用 `target\release` 里的构建产物——首次使用不必先执行 `release\build.bat`。
- **新增架构文档**：`文档/` 下三份并行的成分说明——[功能组分说明.md](文档/功能组分说明.md)（概念术语、功能组、联动与优先级关系）、[文件与执行逻辑.md](文档/文件与执行逻辑.md)（文件清单、模块依赖、三线程模型、一次按键的端到端执行链路）、[设计思想与演进.md](文档/设计思想与演进.md)（设计目标/动机/原则/手法、走过的弯路复盘、后续优化方向）。
